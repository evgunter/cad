## Findings
- **MINOR-1 · `crates/topo/src/boolean/section_cert.rs:744`, `:774`: the plane `Touch::at` stands far off both carriers near the top or bottom parallel. Demonstrated by execution.** `in_pi` divides `n_perp = n − a·n_a` by `s`. For a generic axis that subtraction cancels, so the direction error grows as `ulp/s`. At ×1e3 with axis (1,2,3), a plane tilted 1e-5 rad from axis-normal has `at` 8.9ε off each carrier. At 1e-8 rad (σds still decided) it is 1.19e-5 (1.2e4 ε). The fuzz worst case is 5.4e-4. At ×1, axis (−0.3,0.2,1) and 1e-7 rad give 4.9ε. Red row: `probe_plane_touch_at_off_its_carriers_near_the_top_parallel`. This breaks `Touch::at`'s contract at `:294–296` ("on both carriers within the margin"). The displacement is mostly along the normal, and the touch disc is long there, so the likely effect is that the torus-side placement goes `OffCarrier` → no verdict, which is conservative. I found no wrong body. The pre-existing scrape witness at `:796` uses the same formula, so this is a class, not one instance.
- **NOTE-1:** `mergeable_state: dirty`. `git merge-tree` against main shows one conflict, in `.config/nextest.toml` (the slow-set line this PR extends).
- **NOTE-2 · `:763` and `:822`:** the `!tan.zero` guards repeat `Pinch::touch`'s own `self.zero` check (`:394`). Dropping either changes no behaviour, so no row can pin them.
- **NOTE-3 · `:103`, `:289`, `:392`** still promise "one small loop γ about `at`". A decided near-top plane touch admits a cap about 0.44 rad long on the R = 2 donut at depth ε (half-width √(2ε/(sR)), s ≈ 2e-8). The argument does not need small, as the PR body says, but the docs do not say so.
- **NOTE-4:** the touches the PR unlocks are reachable only where no other layer refuses. Ball and brick poses at the seam, and near-top bricks, stop at `CurvedPierceUnsupported` (counts above). This is scope, not a defect.
