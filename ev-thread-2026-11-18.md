# PR 7068, Ev's comments (verbatim) and the orchestrator's replies (summarised), 2026-11-18

Ev answered decisions 1 and 2 "yes". (Decision 2 turned out to be already ratified: PR 5967, `crates/topo/README.md` tier 3, HELDRECORDS's first unit, now being built.)

On decision 3 ("Between solids, a meeting refuses only at the door that made it… A meeting decided beneath that door (a record it only carried, or an overlap an assembly already reported) keeps the verdict it arrived with… Consequence to see: an assembly's reported overlap then rides the finished body beside its records, as a decision"), Ev wrote, in three comments:

1. "could you elaborate on 'an assembly's reported overlap then rides the finished body beside its records, as a decision'? is this saying that it'd raise the interference lint to something that is an actual decision rather than a lint?"

   Orchestrator: yes in one respect. Nothing decides the overlap and nothing refuses for it, but the fact moves from a lint report (`run_checks`, never persisted) onto the finished body so a later door's gate can read it, which answers `[open.lint-output]` "yes" for that one finding. Alternatives as the designers weighed them: (a) carry records only, so an op working inside the overlap refuses; (b) by door.

2. "i'm confused, is the issue trying to allow self-interfering things that arise from booleans? do we want that?"

   Orchestrator: no. One solid crossing itself always refuses; an overlap a deciding door creates between its result's solids is that door's defect. What passes is only an overlap already in the operand, between two parts of an assembly; `[booleans]` says "`−` and `∩` distribute over `⊔`, so `(p ⊔ q) − t` cuts both and keeps two pieces" and "a meeting inside an operand is never changed by an operator above it". Example: the bolt in the nut (its thread an interference finding), sectioned.

3. "wait, how could - ever create a new overlap

   or is this just about the discrete union case"

   Orchestrator: it cannot. `−`, `∩`, a split and an inward shell only remove material, so any overlap between their result's solids was in the operand. Overlaps are born at a `⊔` (reported) or when a door adds material to one piece of an assembly (a blend filling a concave corner, an outward shell or thicken). So for removing doors nothing need be stored on the body: their gate need not read between solids that descend from different operand pieces. The stored "overlap, reported" fact is needed only for a material-adding door to tell old from new. Told Ev this option ("store nothing; only adding doors look") was not weighed as its own option and is being put to the designers.
