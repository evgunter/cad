# PR 7115: a face holding a vertex at a pole or an apex has an extent that reaches that singular latitude

**Unit:** EMBED's `a-sphere-face-whose-extent-stops-ulps-short-of-its-pole-never-places-the-pole` (unit branch `embed/pole`), from the second engine wave. A sphere face's stored meridian pcurve, read exactly, ends one ulp under π/2, so the face's extent never reached its pole and six valid f64 cavity rows ran out of pairs. The fix is in the one reader: `face_extent` returns the extent reaching the latitude of each pole the face holds a vertex at. After the review the unit grew, by the orchestrator's ruling, to the cone's apex (one reading, `singular_ends`, for a sphere's poles and a cone's apex), and then to a run-on of the collapsed side by key.

**Letter and tier:** M, single, a FULL review. Logged at the second wave's dispatch in `work/embed/log.md` (18 Nov): letter M; tier single FULL for all four second-wave units, "since each changes what the certificate reads or encloses".
