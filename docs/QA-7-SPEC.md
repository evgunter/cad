# QA-7 — CI reports test cost (#469)

Unit spec, S-QA program (`docs/S-QA-PLAN.md` §QA-7). Binding
alongside `docs/prompts/implementer-discipline.md`. **Read issue 469
in full first** — it is the charter and carries the two measurement
traps as spec text: per-leg times are NOT comparable across legs
(sum cpu-seconds per test, never compare legs), and cost
concentrates savagely (report the head, never the mean). Verify its
premises at your merge base: the nextest output shape it parses, and
`scripts/interval-only-selection.py` as the list-diff pattern to
sibling (fail-closed schema handling included). Note the tree moved
since the issue: the test rows now run `--no-fail-fast` and echo
their mode — your parsing must survive both red and green runs.

## Deliverables

1. **Slowest-N per run**: the two sharded test jobs (default and
   interval lanes) print the slowest ~20 tests with cpu-seconds
   into `$GITHUB_STEP_SUMMARY`, summed per test across whatever
   legs the job ran. No permissions, no PR comment, no gate — a
   report. It must not break a red run's step (report generation
   failure must never mask or alter the test verdict — generate
   from captured output with `if: always()`-safe wiring or
   equivalent, and say in the PR how a generation failure presents).
2. **What THIS PR added**: a sibling of
   `interval-only-selection.py` (e.g.
   `scripts/pr-added-tests.py`) diffing `cargo nextest list
   --message-format json` between base and head
   (binary-id, test-name pairs), summing the new tests' measured
   times from the run's own output, into the step summary:
   "This PR adds N tests costing X cpu-s (Y% of the suite)."
   Renames show as one removal + one addition — say so in the
   output the first time it is nonzero. Fail CLOSED into absence
   with a printed reason (a missing base listing is a stated
   skip, never a silent one, and never a red).
3. **Deliberately NOT a gate** — the issue's own ruling; state it
   in the step's comment with the reason (the baseline is moving)
   so a future "add teeth" is a decision, not drift.
4. **The two traps are honored in code**, not prose: per-test
   summation across legs within a job; top-N only. Where the
   per-leg incomparability bites (a job that ran one leg), say
   which legs summed in the summary header.
5. Costs stated: the report must add ~0 billed minutes (parsing
   captured output on the same runner; no extra jobs — the
   billing model rounds per job, `docs/CI-MINUTES-2026-08.md`).
