# QA-6 — the measured-claim sweep, uncontested J-fence legs (#681, PR 1 of 2)

Unit spec, S-QA program (`docs/S-QA-PLAN.md` §QA-6). Binding
alongside `docs/prompts/implementer-discipline.md`. **Read issue 681
in full first** (mcp__github__issue_read, repo evgunter/cad) — it is
the charter: the ratified rule (`docs/prompts/reviewer-style-lane.md`
§Q6) is that a claim resting on a measurement owes a mechanical
guard, a scheduled register that re-takes it, or a written reason AT
THE CLAIM SITE that it can have neither; the issue carries the
instrument (a runnable sweep script), its per-surface variants, its
known holes, and the done condition.

Deferred to PR 2 (say so in the PR body, with the reason — live

## Deliverables

- Each leg names the instrument variant it ran (the issue's script,
  with which marker/extraction) and STATES ITS OWN BLIND SPOTS —
  not the issue's, which describe a pattern some legs do not run.
- Every claim found is classified into Q6's four buckets (guarded /
  scheduled register / unguardable-with-written-reason / unguarded),
  with the disposition AT THE CLAIM SITE — a comment, a guard, or a
  register pointer — never only in the PR body. Guards land where
  cheap (a `const _:` pin, a selftest read); an unguarded row that
  cannot be cheaply guarded is either excused at the site or filed
  as its own issue (durable home, keyword-adjacency-scanned).
- The instrument as actually run is committed if it diverged from
  the issue's copy in more than the marker (the issue's own
  argument: a re-derived instrument inherits a new blind spot —
  disclose it).
- The PR body carries the per-leg tally (blocks scanned → claims →
  bucket counts) so issue 681's checklist can be ticked per leg by
  the orchestrator; the issue stays OPEN for PR 2.

read-only. No workspace builds. Hosted CI green on the PR.
