# FORK-5 — may a geometric slot read a measured value? (designer A)

## For Ev

**Recommendation: no. Stage 2 admits a measured value into checks only.** A `Measure` defines an *observed* variable: a scalar that is a function of the built geometry, not of what was written. An observed variable, and every definition that reads one, may be read by an `Assertion` and by nothing else. A construction's slot (a depth, a radius, a count, a frame, a profile argument, a mate offset) reads only what was written: free variables and definitions over them. The door refuses the other reads typed, and the load walk checks the same rule. Confidence: likely.

**Why this is the semantic answer, not a convenience.** D10's model is intensional: a document says what a thing *is* (this depth is `t`, this cap is `plane(F, n, t)`), and identity, gluing, the lint and the analysis lanes all read that. A measured length is the same geometry with its construction projected away: a number the kernel computed. Reading it back into a construction re-enters a value the way a typed literal would, which is the one thing D10 forbids ("a dimensioned literal stands nowhere"), only now the kernel typed it. Every driven-dimension request I can name has an intensional spelling that keeps identity:

| request | measured spelling (refused) | construction (admitted) |
|---|---|---|
| plug fills a hole of depth `t` | depth := distance(top, floor) | depth reads `t`; or "extrude up to the floor face" (stage 6's constructions, a shared object: glues, certifies) |
| bore sized to a pin in the same document | radius := measured pin radius + c | radius reads `d/2 + c`, the GUI's offer at entry |
| bore sized to a pin in another document | measure the instance's face | AQ4 per-instance arguments (ASSEMBLY, "intended form: `InstantiatePart { …, args }`"), the part's variable read across the seam |
| plug for an imported hole (D7: no variables) | measure the imported face | "up to" the imported face, which has a name; an offset of its carrier for a clearance |

Under the measured spelling the plug's cap `plane(F, n, m)` and the floor `plane(F, n, t)` are not one construction (`m` is an opaque leaf), so the `unproven-coincidence` lint reports a coincidence that in fact holds across the whole family, and its offered edit is "use `t`". The construction spelling is what the lint would send the person to anyway. Admitting the measured one gives the document two ways to say one dependency, one of which erases the intent. That is the condition D10 was written to remove.

**What stays true under the rule (the final state).**

- *A check can never break a build.* A vanished name under a measure poisons the measure and its assertion (`Unevaluated`), never a body. Admission would make a rename in one part refuse a body in another by design, which is `a-failed-requirement-refuses-the-whole-product` reintroduced on purpose. The spec closes that issue in PR C; this rule keeps it closed.
- *Geometry is a function of the free variables alone.* Everything built before the walk from the document's values keeps its meaning: the lane environment and the nominal f64 environment (the content key's nominal word, an authored frame's placement, a section's program resolution), and the mate solve, which runs once before any node and reads mate offsets from that environment. Observed definitions are bound inside the walk, after their measures, at the evaluation's own scalar, generically: one change in PR D, serving assertions.
- *Reversible in one direction.* Lifting the rule later admits more documents and changes no body that builds today. Admitting now and narrowing later breaks documents. The same argument carried rung (2) in PR 3990.

**The alternative, stated fairly: admit (general form).** Any slot of matching kind reads any variable, observed or not; the schedule orders readers after their measures. It is the uniform reading of D10's text, and it covers a quantity used *away from its own construction* (a slot width copied to an unrelated feature's size), which the construction spellings above do not. Its final state is not uniform, though: three exclusions fall out of how evaluation is built, each a refusal of its own.
  1. A slot the mate solve reads (an offset) cannot read an observation: the solve is a whole-document step before the walk, and a measure across two instances already depends on it, a cycle the node schedule cannot see. Stage 3 would have to revisit it.
  2. A slot that pins an f64 decision (a frame's placement, a section's resolution, the pinned lift) cannot read an observation in a non-f64 lane: its nominal exists only after an f64 walk, so the Interval and Dual lanes would need an embedded f64 shadow evaluation. This is the "bind per lane" cost, and it is real only here.
  3. A reader of `min_clearance` has no value on the build path at all: that primitive answers only at `Interval` (`MinClearanceLane` returns `None` at `f64`, `Dual` and `Sym`), so a body depending on it never builds.
  Admission therefore buys the off-site case at the price of three implementation-shaped special cases, a second spelling for every construction, and lint findings on coincidences that hold. The rule above is one special case, stated by meaning, and stable across stages. If a real document needs the off-site case, the recourse is a shared variable, or AQ4 across documents; and lifting the rule is additive.

**The rule, concretely.**

- *Observed* is a property of the definition graph, derived (as acyclicity is), never stored: a variable is observed when its definition is a `Measure`'s output or reads an observed variable. Only scalar kinds can be observed; a `Measure` never defines a `Count`.
- The edit door refuses setting any slot other than an `Assertion`'s `value` or `bound` to an observed variable (typed, naming the slot, the variable and the measure it reaches); defining a variable that is read by such a slot over an observed one refuses the same way; the load walk checks both. Both assertion slots accept observed variables, so "this gap ≥ that gap" is an assertion over two measures.
- Outside an evaluation (`Doc::var_env`, the viewer's value doors, Python's `Var.value`), an observed variable is typed unbound, "measured at evaluation", and its value is read off the `Evaluation`. Inside, PR D's schedule binds it after its measures at the lane's scalar.
- An alternative encoding, which I do not recommend: make observedness part of the kind (`Length` vs an observed `Length`), so a wrong read fails the existing `SlotVarKind` check. It makes the bad state unrepresentable, but it states one fact in two places (the kind and the definition graph) and doubles the scalar kinds.

**Ratified text.** D10 is silent, as the brief says; its "defined … as an output of an operation" plus "every slot holds a variable whose type suits the slot" admits the read by default. The revision is one sentence in D10's Operations paragraph: *"A `Measure` defines an observed variable, a function of the geometry rather than of what was written; an observed variable, and any definition reading one, is read only by an assertion. A construction reads what was written."* Provenance: D10 was written by the designer pair and ratified by you in PR 3990 (decision 1, "the model"); nothing in the PR or its transcripts mentions a measure driving geometry, so this is a gap, not a reversal.

**Confidence.** Recommendation: likely. That every lane is one generic evaluation, so binding is one change, not one per lane: sure (read in `evaluate`, `bind_definitions<T>`, `eval_measure<T>`). That the mate solve runs before the walk over the pre-built environment: sure. That `min_clearance` has no `f64` value: sure. That the construction spellings cover the filed requests: unsure, since I found no filed request (below).
