## For Ev

**Decision asked: stop cross-checking the symbolic tier on decisions the numbers already settled; keep that check as a test, not as part of every run.** Both designers recommend the same final state. (likely)

**Terms.** The kernel decides the sign of a *margin* (a number such as a gap or a turn). At the *symbolic tier* each number carries the expression that produced it, and the tier can prove a margin identically zero by algebra. *Numeric-first* (ratified in E12): where the number already reads a definite sign, that sign is the answer. `Sym<Interval>` is the lane where the number is a certified enclosure (an interval proven to contain the true value); `Sym<f64>` carries one rounded number and is run only by unit tests. The *receipt* is the per-run tally of decisions. A *registration* is a constructor's statement, taken on trust, that two expressions are equal.

**What happens today.** After the numbers give a definite sign, the tier still expands the margin's expression to see whether its algebra would have claimed zero. The answer is thrown away either way: the numeric sign is what is returned. So this is a test of the algebra, run inside every decision. Measured: a finish of a cylinder-walled body takes 842 ms against 2 to 5 ms without the tier, 82% of it on eight decisions the numbers settle every time; on a plain slab it is 95% of all the rule-based algebra the tier does. It blocks deleting the box-scalar switch.

**The final state.**
1. **A definite numeric sign is returned at once.** The tier is asked nothing; a definite decision costs what the numbers cost. This removes both after-the-fact checks: the algebra's, and the one that asks whether a registration would have folded the margin to zero. (sure)
2. **One cheap assertion stays, in every build.** Where the tier answers zero at `Sym<Interval>`, the certified enclosure must contain 0, or the kernel panics. One comparison. It covers every zero whose number was computed by the operations its expression records. It does not cover the one door where they are deliberately different things (the on-surface check for free-form edges: the number there is a measured bound on a distance, the expression is the identity "the edge lies on the surface"; a correct zero can sit beside a bound like `[1e-12, 3e-12]`). (likely)
3. **The old check becomes a test instrument that no shipped build contains.** It asks what the check asked, over all three events (algebra against a certified enclosure; algebra against a rounded number; a registration against a definite sign) and, being off the hot path, over the tier's retry attempts too, which nothing checks today. It runs nightly over the whole document corpus, on any PR that touches the tier, and in small rows on every PR that plant a contradiction and see it caught. (likely)
4. **Four receipt columns go**: `theorems_disputed`, `checks_expanded`, `checks_frozen`, `registrations_contradicted`. Every reader of them today is a test of the check itself. There is no user-facing dial: everything the instrument can report is a defect in the kernel, never a fact about the user's document. (sure)

**What the assertion in point 2 is and is not.** It is not a test of the algebra. A margin whose enclosure excludes 0 by more than the tolerance band is "definite" and never reaches the tier, so the assertion can only fire on an enclosure that excludes 0 while lying inside or across the band. That window is unchecked today, so it is a gain, and it is free. A wrong algebraic zero over an enclosure that straddles 0, the usual case, is visible to no check in any single run, today or after; the instrument in point 3 is what tests the algebra. (sure)

**What is traded.** A run no longer tests the tier's algebra against its own definite margins. A document that has never been through the suite or the nightly corpus therefore gets no such test. We found no record of that test ever catching a defect at `Sym<Interval>`: its recorded firings were at `Sym<f64>`, where the algebra was right and the rounded number wrong. That is the absence of a record in the tracker and logs we searched, not proof. (unsure)

**Why it is sound to stop.** Every definite answer is the numeric channel's and never depended on the tier. The check also already breaks a ratified rule: `[failure]` row 5 says a debug assertion's absence changes nothing shipped, and this one writes receipt columns, so turning release debug assertions off at publish would have changed receipts. Release keeping its debug assertions is untouched. (sure)

**The one ratified sentence that changes** (E12, the registered-identity paragraph): "where a registration WOULD have, the run counts the contradiction (`SymCounts::registrations_contradicted`) instead of folding it away" becomes: "the numeric channel answers first, so no registration turns a margin the enclosure proved non-zero into a `Zero`; where a registration would have, the tier's test instrument counts it, and a registered zero that does decide is asserted against its enclosure." That sentence was written by an agent fix pass (`e80941f1bf`) under your "lgtm" on #1712, not in your words. `[simple.checks]` already says a check may not own a stage or a representation, and needs no change.

**Reversible:** yes; the instrument is the same predicate, and calling it from the decide path again is one line.
