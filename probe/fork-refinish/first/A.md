## For Ev

**Recommendation (likely).** The drive should not cache bodies in its own store. It should use the evaluator's existing node memo across leaves, and bisect only along variables the refusing node actually reads.

- **The unit of reuse is a document node's result**: its build, its finish and its refusal, as one value. It is identified by the node's content key, the hash the evaluator already computes from the op, the bits of its evaluated inputs, the keys of the nodes upstream of it, and ε and K. At a box scalar, the inputs' bits include the intervals of the variables the node reads. So bisecting along a variable the node does not read leaves its key unchanged, and the result can be reused.
- **Where it lives**: in the evaluator's memo. Today that is `evaluate`'s `prior`, which the drive passes as `None`. It becomes one store per drive, shared by the leaves and dropped when the drive ends, as the drive's plain-form memo already is. The drive owns the store's lifetime. The evaluator owns what goes in it and how it is looked up. There is no second cache.
- **Why reuse is sound**: a node's result over a leaf's box depends only on the box's intervals for the variables the node reads (its *support*). Call that the box's *projection* onto the support. Two leaves with the same projection get the same result, by determinism. Every claim the result makes holds over the projection, and so over every leaf that shares it. This is DESIGN's ratified "content-keyed cache transfer" ("the key *is* the correctness proof"), together with `[scalars]`' "the evaluation service … rides the same memoization … no parallel path". **No DESIGN text is needed.**
- **What has to change first**: at the symbolic scalar the key is not yet a proof. Three defects, listed below, have to be fixed before reuse is turned on.
- **The split rule changes.** A leaf bisects on its first undecided node, so the split axis should be the widest variable *in that node's support*. Splitting any other axis leaves that node unchanged, so the child leaf undecides at the same node again and the split is wasted. If none of the support can be split (it is empty, or every axis in it is at its depth budget), no bisection can change the refusal. The leaf then refuses at once, with a typed reason naming the node. That reason is new: no existing refusal says "no split can change this". This is the only provable way to recognise a "refusal no bisection can change".

**What "the symbolic scalar's key is not a proof" means (sure, read in the code).** `Sym` is the scalar that carries an expression beside each interval. A *session* holds a leaf's expression table and its counts. Three things break reuse across sessions:
1. `Sym` feeds only its value's bits to the content key ("provenance is not content", `eval/memo.rs`). Take two depth variables that are both 10 ± 0.1 in a leaf. They give equal keys but different expressions, so a reused value could let a later decision prove `d1 − d2 = 0`. That is an unsound zero. At this scalar the expression is content, because the symbolic tier's decisions read it. Fix: the key takes the node id too. Node ids are already content hashes, so they do not depend on the session.
2. An *opaque* value (one that carries no expression) gets an id from a per-replay counter. Two leaves' "opaque #5" are different reals that would share an id, which is again an unsound zero. Fix: derive the id from the minting node's content key plus an ordinal within that node. Two such values are then the same real, because they come from the same computation on the same inputs.
3. The expression table, the identity registry and the counts belong to the session. A node minted outside the session freezes, so a reused body would lose the symbolic tier. A registration made by an unrelated node earlier in the same leaf can also change another node's answer. Fix: the expression table and form memos become per drive. This is sound because ids are content hashes, and the plain-form memo already makes this argument per drive. A node sees only the registrations of the nodes upstream of it, which ride their values. Counts also ride the node's result.

Item 3 is the substantive change, and it is in geom-core's session, not in the driver (likely: I have not checked every reader of the registry).

**Records and receipts.** A leaf's record already lists each node's content key (`LeafResults`), so a reused node appears exactly as a rebuilt one would. Its leaf record is unchanged. A leaf's decision counts become the sum over its nodes' results, which is the same number a fresh build gives: the decisions its result rests on. The drive's totals become the decisions it actually took, counting each distinct node once. That follows the precedent the `frozen` column set. Telemetry samples (k_stats, the record of every margin decided) are recorded where they are taken, so a duplicate is never taken. E6's promise that every driver-path sample lands in the funnel still holds (likely).

**Premise corrections.**
- **The holes' refusal is not the same in every leaf (sure).** There are 254 distinct hole bodies, so the box does move them. What repeats is the *kind* of refusal: kind A, an undecided length on a direction derived from an end vertex. That is the missing doors-read lane (`the-sweep-doors-read-the-profiles-recorded-directions`), and the fix belongs there, not in the driver. The driver's part is to stop recomputing a refusal whose key repeats, and to stop splitting axes the refusing node does not read.
- **Once kind A is built, reuse matters more (inferred).** A hole finish that succeeds costs about 71 ms against 24.5 ms for a refusing one (M7). So 2,046 of them would cost about 145 s.
- **`m10_8`'s 1.6 s row gains nothing from this (sure, M4).** It runs one leaf per drive and repeats no body. Its levers are finishes per build (ONEHOME's work) and the cost of each finish.

**Ratified text to change.**
- E6, split rule: "max relative width, ties to lowest index" becomes "max relative width among the variables the leaf's first undecided node reads, ties to lowest index; a leaf whose deciding node reads no splittable variable refuses, naming it". Its provenance could not be traced in this shallow checkout.
- E6, leaf protocol: add one sentence: "a node whose inputs a leaf does not change is the earlier leaf's result (DESIGN [determinism])".
- E12 needs no change. Its claim ("zero wherever the build takes this replay's decisions") is made over the node's projection, which is equal across the leaves that share it.

**Alternatives.**
- **B, the parent leaf's evaluation as `prior` for its two children.** This needs no store. It catches the plate in every leaf, but misses "cousins": two leaves in different subtrees with the same projection. That is most of the holes' roughly eightfold repeat. It is easy to grow into the store, so it is a fallback, not a rival.
- **C, the support-aware split alone.** Fewer replays, but the plate is still rebuilt in every leaf.
- **D, hoisting unmoved nodes to the witness or root build.** This is a special case of the memo, and a second path. Rejected.

**Expected effect (unsure, inferred).** On the tour, the plate's 1,023 finishes become 1, saving about 22 s plus its build. The holes' 2,046 finishes become about 254 (roughly 50 s down to about 6 s). The support-aware split also cuts replays wherever the first undecided node reads few variables. How much of the build outside the finishes is unmoved is still not measured, and the memo covers whatever that share turns out to be. Memory use is one entry per distinct node result (about 255 bodies on the tour). It is unmeasured on wider documents.
