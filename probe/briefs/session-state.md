## The unit

Today it also reads the replay's session: what was registered earlier in the leaf, how many retry forms the leaf has already spent, which expressions the leaf's table happens to hold. A later unit will serve one replay's node result to another replay that never ran the node, and it is sound only if nothing with a replay's lifetime is left for a node to read.

**Build, as ratified (point 2 of the row's weighed state, its third and fourth changes):**
1. **The expression table belongs to the drive.** Expression ids are already content hashes and the drive's plain-form memo already argues per drive: the table outlives a leaf. The per-replay teardown that publishes a leaf's forms into the drive's memo and drops its tables becomes one publication per new entry; M9 measured that teardown at 23 s of 178 s on the tour.
2. **There is no per-replay session state a node can read.** Every piece of `Session` is one of three things, and the code says which by where it lives:
   - a CACHE whose hits and misses never change an answer (show that for each: a cap on a cache is safe only if reaching it changes cost and not a result);

The registry a node reads is scoped to the node and its upstream nodes;
   - state that BELONGS TO THE DRIVE and is the same for every leaf: the table, the witness, the brackets `param_over` records (each leaf's own box: say how a served node's brackets are the leaf's).
