## What the change is
The evaluator serves a node from a prior evaluation when its content key and naming key are unchanged. On main the keys did not hash everything an op reads. Inside a family member's evaluation the member bound at the reader's own index stands in for the family, and the keys were taken from that entry, so a read that picks ANOTHER member, or takes the family whole, was keyed by the wrong value and served stale. The PR makes one function, `wire::reads_seen`, say what each read sees (`Stands`, `Member(values)`, `Whole`) and takes both keys from that. It also keys a clearance by its rebuild's point and bodies, refuses a prior made under other run options (the computing twist, the boolean sweep strategy, the symbols), hashes the variable a read comes through in the naming key, hashes a member's place, and bumps the key format version.
