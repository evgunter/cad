## For Ev

**Yes: asking the question of `f64`, `Interval` or `Dual` is a type error. One small decision is left: whether generic code is handed the answer, or only a choice between two spellings. I recommend both, layered, and the designers' two shapes then become one.** (likely)

Terms:
- **`Sym`**: the symbolic scalar, a number carried beside its expression over the document's variables. **Numeric scalars**: `f64`, `Interval`, `Dual` (a value with its derivatives), and the test scalar `Probe`.
- **The question**: "is this value identically zero in the document's variables?", answered by the symbolic tier with every value-reading rule off.
- **Spelling**: one of two formulas for the same real value (the axis `(0, ±1)`, or the chord over its length). **General spelling**: the one that is right everywhere.
- **The mint**: the one function that makes a segment's unit direction.

**The final state.**
1. **The question belongs to the expression, not the scalar.** Each scalar declares the expression it carries. `Sym` carries its node in the document's expression graph. The numeric scalars carry none, declared by a type that has no values, so there is nothing to put the question to. The trait already does this once: `Real::Carries` gives `Dual` no certificate by the same device. Writing the question against an `f64`, or against a generic scalar directly, does not compile. (sure it is expressible)
2. **The answer is a proof token** that only the symbolic tier can make. There is no answer meaning "no" or "differs".
3. **Generic code normally never sees the token.** One helper, built on (1) and (2), takes a value and two spellings and returns one of them: the closed spelling where the value's expression is identically zero, the general one otherwise. The mint is written with it:
   - "if x is identically zero: the axis `(0, sign of y)`; else if y is: the axis `(sign of x, 0)`; else the chord over its length."
   - At a numeric scalar the helper can only return the general spelling, by type, and the sign reading inside the closed spelling does not exist there.
4. **The token is used directly only by the few sites that need an answer about several values at once**, on a kept list with a gate. Today that is none in production; the candidates are "all these weights are one value" and "these two unit vectors are the same direction" if they are kept as structural shortcuts.

**Why layered and not one or the other.**
- *Only the helper* (one shape proposed): the scalar trait gets a method "pick a spelling" that every numeric scalar implements by picking the general one. That is tidy for one value. But it is again a method a numeric scalar holds and answers trivially, and each new kind of question (two values in constant ratio, an identity to register) needs another such method. It also does not truly hide the answer: a caller can pass "yes" and "no" as the two spellings and read it back. So the licence is held by review either way.
- *Only the token* (the other shape, and mine last round): general, and one home for everything only `Sym` can do. But every caller is handed an answer it could branch on for anything.
- *Layered*: the expression is the one mechanism; the helper is the normal door and keeps the answer inside the choice; the bare token is the exception, listed. (likely)

**What the licence rests on, honestly.** "The answer may only choose between two spellings of one real value" cannot be fully enforced by types under any shape. What the types give: no numeric scalar can be asked; there is no "no"; and through the helper the answer does not outlive the choice. What review and the list give: that the two spellings are the same real value, and that the direct users are few. A check in the symbolic lanes that the two spellings agree at the value channel would cover most of the rest. (likely)

**Nested scalars.** `Sym` over `Dual` exists in the tree's tests. It carries an expression, and the closed spelling is right there: a value that is identically zero has zero derivative too. `Dual` over `Sym`, if it ever appears, carries none, like every `Dual`, so a coincidence at the seed cannot store a constant with a lost derivative. `Probe` carries none. (likely)

**State the principle generally.** Two existing hooks have the shape you objected to: `Real::register_equal` (a numeric scalar "registers" an identity and records nothing) and `Decide::free_identity` (a numeric scalar returns itself). Under this shape both move onto the expression with no second mechanism. So the ratified sentence should be about the expression, not only about this question, and it will not need re-ratifying when they move. This PR does not move them.

**Replacement text, DESIGN `[scalars]`:**
> - **What only a symbolic scalar can do is offered by its expression.** Each scalar declares the expression it carries: `Sym` its node in the document's expression graph; `f64`, `Interval` and `Dual` none, by a type with no values, so nothing symbolic can be asked of them and such a call does not typecheck. **The structural question**, whether a value is identically zero in the document's variables, is a method of the expression. It is answered by the symbolic tier with rules that read no value and a budget no session sets (ERROR-DESIGN E12), so the answer never comes from the value channel and is the same at every valuation; it is a proof, and there is no answer that means "differs". Code generic over the scalar offers two spellings of one real value and receives one: the closed spelling where the value's expression is identically zero, the general spelling otherwise and at every numeric scalar. The proof is read directly only at listed sites. The question is not a decision: it reads no sign and no band, counts and records nothing, and defers nothing; a branch that changes what is built is a decision ([verdicts]). At a numeric scalar zero is the band's ([verdicts]), and a zero that means something is a variant, never a number read back ([unrepresentable]).

**ERROR-DESIGN E12:** "A numeric scalar is never asked." becomes "A numeric scalar carries no expression, so the question cannot be put to it (DESIGN [scalars])."
