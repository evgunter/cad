**What the viewer's forms answer, and in how many vocabularies.**
*What is this button waiting for*, *is this seat empty*, *how fast
does this field drag*, *which dimensions have a unit*, *how many ways
may a circle split*: each question has several homes, and the homes
already disagree in places. Two rows are the seat gate those forms
consult: `combine::denotes_body` judges a body seat by node kind
where the evaluator reads a value, and a projection's source can only
be picked from the tree.

Charter and order: `work/formwords/plan.md`; narrative in
`work/formwords/log.md`.

## From FORMS (merged 2026-11-20)

FORMS — one editor per node kind: creating a thing commits it and hands it to the edit surface

**Creating a thing and editing it are one implementation.** Ev
(chat, 2026-11-01): every node kind with a create form and an edit
panel has two implementations, and the rule is one for the whole
viewer, with (a) preferred — *a create gesture commits the node and
the node's edit surface takes it from there*, so every change made
while creating it is an ordinary edit that undo reaches. The add-profile
form is the instance Ev hit first; the extrude and revolve forms,
which take no variables, are the next; the seated tools follow.

One row is a profile-language question Ev raised on the same ground:
a profile step cannot refer to the profile's own earlier points.

`docs/doc-ledger/forms-merges-into-formwords.md`.
