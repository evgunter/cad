## What

`demos/tour/src/tessbudget.rs:53` builds the sweep's scene key as `format!("{}/{}", stop.name, sb.name)` and nothing guarantees it unique. Since `C15`, `tools/tess-lint`'s `parse` REQUIRES it — a repeated `(scene, face)` is harness breakage, because every index by that key would otherwise resolve the collision by keeping whichever row it saw last — so the tour owes a uniqueness guarantee it does not record. Cheap, and cheaply broken: two bodies of one stop sharing a name, or a `/` in either name

## Landed

**The guarantee is now MADE, in the driver, and it fails loud.** `tessbudget::run` carries a `HashSet<String>` of scene keys across the whole walk and two `assert!`s at the body loop:

- **the seen-set** — a repeat panics naming the key, which covers two bodies of one stop sharing a name and two stops sharing one;
- **a `/` ban on both components** — checked before the `format!`, so the formatting stays INJECTIVE and the panic names the pair that broke the namespace rather than whichever body happened to arrive second. Without it the seen-set would still refuse the collision, but at the wrong site: two distinct `(stop, body)` pairs can format to one key.

Panics rather than dedupe or rename, per the project's fail-loud posture: the sweep's whole output is a measurement, and a demo that quietly renamed a body would hand the gate a CSV it could not say was wrong.

**The contract this guarantees, read off the consumers rather than assumed.** `tess_meter::CSV_HEADER` opens `scene,face,...` and `FaceRow::csv_row` writes the caller's `scene` string verbatim as field 0; `face` is the mesh-patch ordinal `tess_meter::face_rows` assigns, unique within a body by construction. `tools/tess-lint`'s `parse` (`lib.rs:595`, `:717`) keys a `HashSet<(&str, usize)>` on `(f[0], face)` — the WHOLE first field, which it never splits on `/` — and refuses a second row for a pair with *"the per-face join needs one row per face"*. So uniqueness of the join key over the sweep is exactly uniqueness of the scene key over the walk, and the driver is the only place that can supply it: the names are the tour's.

A third shape — a `,` or a newline in a name — is deliberately NOT checked here: it would widen or split the row and `parse` refuses on the field count before it ever reads the key. Stated in the code so the omission is a decision rather than a gap.

**Not touched, and not this row's to touch:** what a durable per-FACE name should be is Track K's `D201`, which says explicitly that it reaches `crates/topo` and `demos/` and is unsettled. This row is the scene half of the key only.
