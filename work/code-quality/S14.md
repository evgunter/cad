## Question

**What the no-panic principle actually says.** Ev's reframe,
2026-08-18: *"maybe we need to update that principle to 'no panic on
any reachable state, yes panic on things that can only indicate
bugs'"*. The two halves separate: *no panic on any reachable state* is a
**clarification** — D9 already says "on any input" and no existing
`debug_assert` moves — while *yes panic on things that can only indicate
a bug* is an **amendment**, because it licenses panics in release, which
D9 does not, and on the one such class D9 disposes of it chose typed
error or garbage-out. The reframe is also in the tree unnoticed: PR #447
argued for panicking indexing on the merits and never took it back to
D9, while `crates/topo` is ratified the other way.

**The witness is `topo::instance`'s graft — `S14(b)`.**
`graft_disjoint_all_keyed` is a public door that can leave a body
**tier-1-invalid**: it mints an empty destination solid per source solid
before transplanting, and its own docs state that a refusal raised
mid-transplant leaves `dst` partially written and *spent, never
resumable* — an empty solid being `SolidWithoutShells`, a tier-1 error.
The mid-transplant refusal these doors can raise is `JoinDesync`, from
the reference remap, and it writes as it goes. So a caller that discards
the `Err` and keeps the body makes the next Euler operator's
`debug_assert` fire from **API misuse, not a kernel bug** — precisely the
class D9's footnote asserts cannot occur, and which `S43`'s proposed
sixth state class named while the ratified five do not cover it. It is a
documented failure mode of a shipping API, conceded in writing at the
door.

**Row 0 of the D2 addendum asks the prior question and does not answer
it** (ratified Ev, 2026-08-20): *can the type stop representing the
state?* — here, can `graft_disjoint_all_keyed` be restructured so a
partially-written destination is not representable, staging into a
fresh body and committing on success, the shape `merge_coplanar_faces`
already uses in the same crate (`merge_faces.rs:468`, `let mut work =
self.clone()`, under its own *"Never a partial commit: each sub-stage is
tier-2-gated before adoption"*)? Whether that restructuring is
affordable is row 0's *"if possible"* judgement and it is **Ev's** —
which is why no row exists for it; if the answer is *yes, restructure
it*, that is a row worth minting at that moment.

**It is a bound on other lanes, not only a taxonomy gap**: the `fillet`
lookup sites #740 left as typed errors rather than `unreachable!` stand
that way because this question is open.

## Finding

**What is open here is S14(b).** #823 split this row in two. **S14(a)**
was the `Span`/`KnotVector` pairing in `geom-core`/`geom` — a mismatched
`Span` indexing out of bounds through the public API — and it is closed.
**S14(b)** is `topo::instance`'s graft leaving a partially-written
destination: `graft_disjoint_all_keyed` mints an empty destination solid
per source solid before transplanting, and a refusal raised
mid-transplant leaves `dst` partially written and spent, an empty solid
being `SolidWithoutShells`, a tier-1 error. The two halves share a shape
and nothing else, and neither blocks the other.
`DESIGN.md:1358-1375`'s ratified row-0 paragraph about "S14" describes
**S14(b) only**; it names neither `Span` nor #475.

**It is a decision rather than work.** Row 0 of the D2 addendum reframed
its first question without answering it: can `graft_disjoint_all_keyed`
be restructured so a partially-written destination is not representable
— staging into a fresh body and committing on success, the shape
`merge_coplanar_faces` already uses in the same crate? Whether that is
affordable is row 0's *"if possible"* judgement, and it is Ev's. **`S70`
is S14(b)'s documentation residue** and is decided with it.

**Its practical bite is a bound on other lanes**, not only a taxonomy
gap: #740 left its `fillet` lookup sites as typed errors rather than
`unreachable!` because this question is open (~45 announcement sites
under the criterion #823 re-derived, and the figure belongs to S14(b)).
