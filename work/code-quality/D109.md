## Finding

### S163. What the F3 sweep left open in `scripts/gates/` — four members, one row

Raised by lane **F-g** while closing S63 and S157, and **grown by that PR's style and adversarial reviews** — the members with numbers attached are the ones those reviews added. One row (**D109**), because each is a disclosed blind spot of the same sweep and a reader who takes one should see the others.

**(b) One gate is off the shared reader on purpose, and it is the one that decides the reader's interface.** `probe-suite-census.sh`'s probe-gate matcher looks for `#[cfg(feature = "probe")]` — **its needle contains a string literal**, so the code-only view would blank exactly what it wants. What it wants is `code_and_literals` (comments stripped, literals KEPT) — **one of `test_utils::source`'s three views, not a fourth** — and that is the one of the three `gate_rust_code` does not build. Its matcher is anchored at column zero instead, and it carries a prose fixture because of that. **#849's first record claimed no gate here greps for a string literal**, which was the whole argument for building one view; the argument still holds for the gates converted to the code-only view, but as a statement about them, not about the directory. (Note: `probe-suite-census.sh` and `gate-roster.sh` are outside this track's fence; `D208` is the row for the *description* of this view in `lib.sh`, and this member is the row for *building* it in the shell reader.)

**(c) The shared reader is a lexer, and says so.** Nested block comments (Rust allows them; the first `*/` closes here), `macro_rules!` bodies, `include!`d text, and anything behind a `#[cfg]` other than the `test` skip are all read as ordinary code. Only a **test-only** attribute may exclude — `any(test, …)` and `not(test)` are both scanned, since `any(debug_assertions, test, …)` is every debug build (`topo`'s `test_support_impl` is exactly that, and an earlier draft skipped it). An ALL-CAPS operand (`SOME_CONST * SOME_CONST`) and an indexed square (`v[i] * v[i]`) are both invisible to the square matcher, the first deliberately (the ALL-CAPS population here is `usize` sizing) and the second not.

**(d) 9 of 80 `gate_error` call sites in `scripts/gates/` are reached by no self-test case**, re-derived 2026-09-03 by instrumenting `gate_error` with `BASH_SOURCE`/`BASH_LINENO` and tracing all fifteen `--selftest` runs. Re-derive it the same way rather than trusting this number: the population grows every time a gate gains a guard, and the count above is a reading, not a register.

Six of the nine are **outside this track's fence** — `gate-roster.sh`'s missing-local-half, empty-roster and *"loops the gates but never runs one"* guards, and `probe-suite-census.sh`'s nested-suite diagnosis (the one inside the command substitution that motivated the stdout→stderr move), its missing-`SWEEP_SCRIPT` guard and its missing-`ci.yml` guard. Both files sit on retired Track `J`'s unowned ground, so their fixtures are a row to be drawn there, not work this track can take.

The other three are in fence and are **unreachable as the code stands, which is the finding**:

- `lib.sh`'s *"defines no `gate_selftest`"* guard — unreachable while every gate defines one, and the only fixture that would reach it is a gate written to have no self-test.
- `signed-zero-one-home.sh`'s *"no `.rs` files under the scanned directories"* guard is **dominated by the `gate_require_file` call immediately above it**: the home file it requires (`crates/step-import/src/signed_zero.rs`) lies inside the first scanned directory, so a tree that clears the first guard always yields at least one file. It can fire only if the scan directories grow to a set the home file is not in.
- `interval-square-allowlist.sh`'s *"every source … is test-only"* guard (**named, not numbered, per G-R13** — it moved twice inside #885 alone) needs `production_sources` to exclude *every* file. That set is derived from `#[cfg(test)] mod` declarations, and a declaring file is never in it, so the file at the top of every declaration chain always survives: the guard can fire only on a **cyclic** module-declaration graph, which is not a tree `rustc` accepts.

**`lib.sh` says a guard never shown to fire is not a guard**, and each of those three is that sentence pointed at a specific line: either the guard is reachable and owes a fixture, or the code above it makes it dead and it owes a decision. The count is here rather than a caveat so that it can be worked down.

**(e) The real-scan cost went from ~4.5 s to ~48 s across the six converted gates**, measured on the F-g lane container (a shared box at load average ~12, not a runner): 5.9 / 6.2 / 6.0 / 9.6 / 11.3 / 9.5 s against 0.5–1.0 s each before, and both halves of CI run every gate twice (`--selftest` then the gate). **On the hosted runner the whole `discipline` job is 30 s against a 23 s pre-change baseline and every gate step is 0–1 s** (runs `32439375293` and `32388258102`), so nothing is at risk today — the number is here because a tenfold aggregate change should be findable by the next person rather than discovered.
