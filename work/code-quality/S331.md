## What

**`validate_pcurves` answers a clean bill on a body whose mint just failed (filed by CERT-N2; found by the dual review, executed).** `topo/src/pcurves.rs:1602` returns an empty error list for a body where `mint_pcurves` refused a face and `clear_face_caches` removed its caches — absence of a cache is not a claim (`validate_pcurves`' own rule), so zero errors is the correct *letter* and a vacuous green through a **public** door: a caller that validates after a failed mint is told the pcurves are fine. The question is whether at-rest validation should distinguish *no cache because this class is uncovered* from *no cache because minting refused*. **Fence note**: `topo/src/pcurves.rs` is named by neither this track's file list nor Track Q's, so this row draws the fence rather than assuming one — it is placed here, beside `validate.rs`, because the question is what at-rest validation may claim; the pcurve certification machinery it consults is Q's `pcurve_cache.rs`.
