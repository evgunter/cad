## Finding

### S168. The recording scalar is asserted to be a wrapper by no test

Three tests in `crates/editor-core/tests/` stand where a differential between the recording scalar and f64 would go: `m5_pr5_corpus_probe.rs`, and `m4_pr8_k_probe.rs`'s `corpus_evaluates_green_at_probe` and `run_doc`.

**All three assert one-sided GREENNESS at `Probe`. None compares a `Probe` result against an f64 one**, and no test in this tree does. Greenness is evidence for bit-identity and is not a check of it — a `Probe` lane that decided differently but still produced a valid body would pass every one of them. Greenness is also **tolerance-dependent**, which a *"bit-identical"* framing hides: it is why the dump is swept at three ε, and it is why the argument *"there is nothing per-ε about this claim"* was wrong.

So the wrapper property — *the recording scalar is a wrapper, never a different arithmetic* — is checked by nothing, and the two tests F8 exists to make run are where the check would sit. That gap is **D114**.
