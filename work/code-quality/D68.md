## Finding

### S124. A compound bound given a NAME is invisible at its use sites, and the gate header says the opposite

**[verified]** `crates/profile/src/path/arc_fillet.rs:593` declares `pub trait ArcCarrierScalar: Decide + Bounds {}`. The **declaration** fires `bounds-allowlist.sh` (it writes the pair literally) and `arc_fillet.rs` is allowlisted for it under ruling LB3. Every **use** of the name is a `Decide + Bounds` bound the gate cannot see. Re-derived 2026-09-03 by this lane, sweep definition beside the result: `grep -o 'ArcCarrierScalar'` over `crates/`, counting **occurrences of the identifier**, not lines — **63 tree-wide**, of which **52 are in the two path files** (`family.rs` 27, `program.rs` 25) and **50 of those 52 are bounds** (each file spends one occurrence on its `use` line, `family.rs:135` and `program.rs:95`). The other eleven are the declaration and its blanket impl (`arc_fillet.rs`, 2), the three re-exports, and six in `crates/*/tests`, which this gate does not scan. The 50 sit on `pub` and `pub(super)` fn signatures, on four public trait declarations (`ArrivalSpec`, `TangentIncoming`, `PointIncoming`, `LegEndIncoming`) and on `PartialPath` impl blocks. The name is re-exported from `profile/src/path.rs:364`, `profile/src/lib.rs:133` and `pncad/src/profile.rs:57`, so the pair is `pub` from the top-level crate.

The gate header's arc_fillet entry said *"Confined to this one file so path.rs itself stays bracket-free"*. The **literal spelling** is confined; the **bound** is not. #791 corrected that sentence and recorded the hole as the gate's KNOWN GAP 3, rather than closing it by grep — closing it by grep means redding two files and allowlisting them, which is the cry-wolf-then-allowlist outcome S63 already records at `linalg/mat.rs`.

**This is the same class as S59 one level up.** S59 was a matcher blind to an alias *name*; this is a matcher blind to an alias *use*. Whether these 50 sites are legal depends on what `ArcCarrierScalar` is bound to, which is **S87**'s question (§D row **G4**).

**G4 does not discharge this, and saying otherwise would be a disclosed blind spot read as a discharge.** G4 changes what the alias is *bound to*; the 50 uses stay exactly as invisible to this matcher, and `bounds-allowlist.sh`'s KNOWN GAP 3 is as open after G4 as before. Two different jobs: G4 decides whether the sites are legal, D68 is whether they can be *checked*. The same correction bears on G4's own evidence — the widened matcher fires on **none of G4's sites** (`arc_fillet.rs` is allowlisted by file, the uses are alias-shaped, `geom`'s doors are sole bounds), so a green gate there is not ratification evidence.

**And the matcher's own version of the same hole is KNOWN GAP 4**, added by #791: an alias whose name does *not* end in `Bounds` is invisible at its uses too. Its mitigation — the declaration writes the pair literally and fires, so the declaring file must be ratified — is planted in the gate's self-test rather than asserted, which is the shape D68 should close in.

## Answer

**The only close available for the 50 sites is the one `S63` forbids,
and that is the row's answer.** Not "not worth it", not "later", and —
this is the correction the row's own instrument forced — **not
"impossible for an instrument of this kind"**. Every site is
`T: ArcCarrierScalar`, character for character the sole bracket bound
`plant_sole_bracket_bounds` pins as must-NOT-fire — *"a matcher that
fired on it would red geom-brep/src/ssi/enclose.rs, geom/src/net.rs and
both geom nurbs files"* — so no WIDENING of the shipped matcher reaches
them.

**But a name-resolving pass is not what it takes.** A matcher keyed on
the ROSTER's own name list separates the two with no resolution and no
second pass:

```
gate_grep -E "[A-Za-z0-9_][[:space:]]*:[[:space:]]*(ArcCarrierScalar)\b|\+[[:space:]]*(ArcCarrierScalar)\b"
```

It PASSES `plant_sole_bracket_bounds` and its output over `crates/*/src`
is `family.rs` (26 lines) and `program.rs` (24) and nothing else,
measured 2026-09-03. So the sites ARE separable by a name-shaped
matcher; what is true is the narrower thing this row also says — its
output is exactly the two files the row must not red-then-allowlist,
which is the cry-wolf-then-allowlist outcome `S63` records at
`linalg/mat.rs`. The disposition does not move; the reason does. **The
irony is worth carrying forward rather than repeating**: this row built
the roster — precisely the ratified list of names such a matcher needs —
and then wrote a negative the roster defeats, in the same file, three
screens apart. The negative was the load-bearing sentence and it was the
one nobody re-derived.

**No allowlist entry was added by this row**, and whether those sites
are legal is untouched: that is `S87` / `G4`.

**The argument is executable rather than written.** The fixture
`plant_alias_uses_invisible` plants the declaration in its ratified
home and the three use shapes `family.rs` actually writes — a free fn, a public trait generic
over the name, an impl block — in a file no filter names, and requires
the gate to **PASS**. GAP 3's invisibility to the shipped matcher is now
a measured fact that goes red the day the matcher is keyed on the
roster's names.

**What was buildable is the PREMISE, and it is now checked.** GAP 3's
whole defence is that the declaration is written in a spelling the
matcher catches and sits in a ratified file. That was asserted in the
header and guarded by nothing. `BOUNDS_ALIAS_ROSTER` plus
`gate_alias_roster_census` check it. The roster is a register of names
whose uses are unchecked, and it changes no SCAN hit — but it is **not
inert**, and calling it "an exemption of nothing" was the second
overstatement here: the entry is exactly what makes the CENSUS green for
the name it lists, and the cheap green for `plant_new_alias_in_ratified_file`
is a new roster line. It is an exemption surface for the check it
shipped with, which is why an entry must name the ratification that
licensed the name. Five green→RED transitions, each planted, none of
them a use site: the declaration going quiet where it stands (the
rustfmt `where` block, GAP 4's formatter-stable spelling); the same
declaration renamed; a new alias — compound or bracket-only — minted
inside a file the list already ratifies, where the scan is silent; and
the alias RETIRED, its file gone and its entry left standing. That last
one closed a hole the header had asserted away: an entry naming a path
the tree does not have was silently accepted, on the live tree and in
the self-test, while the header claimed *"its entry leaves in the change
that retires it"* with nothing checking it. Nothing went RED→green: the
pre-filter hit set over `crates/*/src` is byte-identical before and
after — re-derive it as `gate_rust_code` over `find crates/*/src -type f
-name '*.rs'` through the gate's matcher and `gate_definition_skip`,
rather than trusting a count copied here (`D208`'s ruling) — and every
pre-existing self-test case holds.

**Its false-positive class, enumerated**: a bracket-ONLY alias
declaration (`trait X: CertifiedBounds`) is asked for a roster entry
although its uses are outside this gate's class. That is deliberate — the
roster registers a name the matcher cannot read through, not a verdict
that the name is illegal, and the entry is where somebody says which of
the two it is. It is planted as
`plant_bracket_only_alias_in_ratified_file` rather than left to be met.
A second class was found and kept OUT:
`trait ArrivalSpec<T: CertifiedBounds>` — a sole bracket bound whose
parameter colon the main matcher already reads as a supertrait colon.
The census reader skips a balanced `<…>` so it does not inherit that; the
main matcher is untouched and the live false positive is filed as
`trait-generic-sole-bracket`.

**What this row did not touch.** `D102` — the census reads declarations
through the same line-based, `+`-anchored alternative and inherits every
spelling it misses; the roster reports that the declaration went quiet,
never why, and cannot tell a reformat from a rename. `D103` — the roster
is keyed by name and sits beside the file list without replacing it or
ratifying it; the ride-along it closes is the DECLARATION sliver of
GAP 6 and nothing else, and a second ordinary compound bound in a
ratified file is exactly as silent as before. The issue `unanchored-definition-skip` — its two patterns were moved
into one function so the census and the scan share them, which neither widens nor narrows what they exempt.

**`G4` is not unparked by this row, and its trigger is now stated
truly.** `G4` waited on *"Track K's allowlist answer … or an allowlist
row filed there (UV-R8)"*. This row is that answer and minted no entry,
so what discharges UV-R8 is this row reaching main — `G4` is parked on
the PR, not on a Track K row it cannot see move. The gate-side edits the
retirement carries are `D212`, which RIDES WITH `G4` rather than
blocking it. What changed for `G4` besides: the retirement is now **loud
in two places** — deleting the declaration reds the census until its
roster entry goes with it, and so does deleting the file.
