## Finding

`crates/bvh/src/lib.rs`'s *Bounds scope* section states the gate's
current behaviour — *"`crates/bvh/` is not on its allowlist, so a
`T: Decide + Bounds` in this crate fires today — the 2026-07-29
amendment names the crate, but a ratification in the rule is not one in
the allowlist"* — and stops there, so the mismatch reads as an
unsettled one. It is settled: `scripts/gates/bounds-allowlist.sh`'s
header now records the absence as **deliberate**, with the reason (the
crate writes the SOLE bound everywhere today; a filter is owed by the
first file that writes the compound one, and until then the red is what
puts the amendment's driver-code scope in front of whoever writes it;
a crate-wide filter would exempt files that do not exist yet).

The note is still TRUE, which is why the closing lane left it alone —
`crates/bvh/` is Track M's, and D209's disposition was made from Track
K's side of the fence. What it owes is a pointer to that disposition,
so a reader of `bvh` does not read a live mismatch and "fix" it by
adding a filter for a crate with no compound bound in it.

Measured 2026-09-03, not asserted: a `pub fn f<T: Decide + Bounds>` planted
in `crates/bvh/src/aabb.rs` reds the gate (`crates/bvh/src/aabb.rs` +

plant was reverted.
