## What

**`S177`'s remainder — walk every OTHER struck lane row for rides-along
that left with it.** Findings routed to an already-dispatched lane ride
along on that lane's row rather than taking rows of their own; when the
lane lands, the row leaves under the *live rows only* rule and the
rides-along leave with it, whether or not the lane touched them, because
a rides-along has no other index. `D124` executed the sweep for the one
instance `S177` enumerated — Track E's `E-g`: four members, `S111(a)`
verified closed, `S111(b)`, `S111(d)` and `S112(a)` re-homed as Track T's
`D322`–`D324` — and deliberately did not touch the rest. Every closed
lane on every track has the same exposure.

**The rule half is in place**: a row may only close once each
rides-along it did not close has been re-homed or given its own file
(`plan.md`, *How to read an item*; enforced by `rides_with:` and lint),
so the accrual is stopped going forward. **What is left is the walk**:
every row struck BEFORE that rule existed, which is all of them — read
each closed track's execution record under `logs/` for the rides-along
its landing reports listed, check each against the tree, and give every
one still standing a file of its own with citations re-derived.

## Why last

Program-wide, and it audits this program's own history rather than any
track's files — a rides-along is only visible from a landed lane's
report, so the walk crosses every track's log and can be scoped to no
fence.
