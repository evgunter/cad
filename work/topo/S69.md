## Finding

### S69. `kfmrh`'s shell-fusion form is outside the fuzz catalog, and the `Ledger` counts solids, so it cannot notice

S15's finding was that `split_edge` shared `mev`'s Euler vector while sitting outside the fuzz catalog; the fix added `SplitEdge`. Meanwhile `kfmrh` gained a cross-shell **shell fusion** form (`crates/topo/src/euler_ring.rs:809` — re-homes faces, kills a shell, `ArenaDelta { shells: -1 }`), and both `kfmrh_candidates` (`seqgen.rs:502`) and teardown's re-make search (`:1103`) filter on `face1.shell == face2.shell`, so the fusion branch is **never generated**.

The `Ledger` cannot notice either: its `s` is the *solids* count (`seqgen.rs:283`), not shells, so a shell-count error passes property (b) silently.

Related, same operator: `euler_ring.rs:846-862` hands `assert_euler_postcondition` an `ArenaDelta` computed as `if killed_shell.is_some() { … shells: -1 … } else { … }`, where `killed_shell` is produced by the same `cross_shell` branch that did the mutation. The postcondition therefore follows the code down whichever path it took and can no longer detect the fusion branch running when it should not have. Every other operator hands it a constant, and `euler.rs:869` describes `ArenaDelta` as *"One operator's signed shift"*, named at the site *"so a site reads as the op's actual shift"*.

Dispatched as the generator sub-lane's unit. Branch
`topo/s69-kfmrh-fusion-form`. Outside the A/B experiment (single style

Three defects, one operator, in order of what they cost:

1. **The fusion branch is never generated.** `kfmrh_candidates`
   (`crates/topo/src/seqgen.rs:502-512`) filters
   `face1.shell == face2.shell`; teardown's re-make search
   (`:1095-1112`) does the same. `kfmrh`'s cross-shell form
   (`crates/topo/src/euler_ring.rs:~809-835`: f2's surviving faces
   re-home into f1's shell, f2's shell dies, `ArenaDelta { shells: -1 }`)
   therefore has no witness in the fuzz corpus. Add the form: pairs in
   the SAME solid and DIFFERENT shells with `face2.rings.is_empty()`
   (the plan phase's own precondition — read it and cite it; `CrossSolid`
   is the refusal for the other case). Multi-shell solids exist in the
   corpus wherever `mfkrh` has run; measure how often the new row is
   askable and drawn over the standard effort, and put the number in
   the PR body with the seed. Teardown's search takes the same widening
   or says why not.
2. **The `Ledger` counts solids where the identity wants shells.**
   `seqgen.rs:~283`'s `s` is `body.solids().count()`; the Euler–Poincaré
   identity's `S` is shells, so a shell-count error passes property (b)
   silently — which is exactly what defect 1 would produce if the fusion
   branch got its count wrong. The ledger carries shells (and solids
   beside it if a property reads them); property (b) is restated on the
   right term. Then show the row is live: plant a mutant in the fusion
   branch that leaves `f2_shell` alive (skip the `self.shells.remove`)
   and show (b) reds; revert.
3. **The postcondition follows the code down its own branch.**
   `euler_ring.rs:~846-862` hands `assert_euler_postcondition` a delta
   chosen by `killed_shell.is_some()`, computed by the mutation it is
   checking, so a fusion that ran when it should not have is invisible
   to it. Derive the expected delta from the PLAN phase's decision
   (`cross_shell`, decided before any mutation) and hand the
   postcondition that constant; `euler.rs:869`'s "one operator's signed
   shift" then holds. Mutant: make the mutation take the fusion branch
   when the plan said not to (or vice versa) and show the postcondition
   reds; revert.
