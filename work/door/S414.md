## Closed (2026-09-11)

Fixed in `crates/step-import/src/geometry.rs`' conic arm, with two
refusal tests in `crates/step-import/tests/probe_refusals.rs`.

**The shape is not the hoist the row wrote.** The existing check tested
`t0` and `t1` together and the self-loop path has only `t0`, so there
was nothing to hoist. The angle closure now answers
`Result<f64, StepImportError>` and refuses at the point of derivation,
so the early return has no check left to outrun and no future edit can
re-open the ordering. Both returned parameters are finite by
construction, which also makes the `while t1 <= t0` wrap loop provably
terminating.

**The row's premise is wrong on one point, and the message changed for
it.** `atan2(0.0, 0.0)` is `0.0`, so a vertex *at the conic's centre* —
the case the old refusal text named — produces a finite (and wrong)
angle, never `NaN`. It is declined downstream by the adoption gate's
`EndpointStart` residual, which is pinned by a second test. The
non-finite angle comes from non-finite vertex or placement data, or
from a semi-axis of zero (`0.0 / 0.0`); the new message names those and
not the centre.

**Behaviour change**: a STEP file that reached this path previously
imported as far as the adoption gate with `(NaN, NaN)` parameters and
was declined there as `Adoption { .. ParamSpan Indeterminate .. }`; it
is now refused at the door as `Topology`. Class **E** was right.
