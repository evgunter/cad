# `work/issues/` — items no program owns yet

**This directory is for issues that do not have a home yet, not a
waiting room for issues whose owner is obvious.** When the owning
program is clear, file the item directly onto that program's slate
(`work/<program>/<id>.md`) — a lane does not need the owner's
permission to put a finding where it belongs. (Ev, 2026-09-04.)

An item here is claimed by MOVING it, header edit and `git mv`, never
by copying: see `work/README.md`, which is the contract this file only
points at.

**It is empty of live items as of 2026-09-11.** The cut recorded in
`docs/WORK-TRACKS-2026-09.md` addendum 3 read the thirty-one non-closed
files here together with the seventy-nine in `work/code-quality/` and
moved all 110 into eleven programs opened for them. What is left here is
closed items and this page. That is the directory working as intended,
not a change to it: an issue with no home yet still lands here, and the
rule above still decides whether it should have gone straight to a
program's slate instead.
