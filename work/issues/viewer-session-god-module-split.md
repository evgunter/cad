**The observation.** `crates/viewer/src/session.rs` is ~2,400 lines holding nine-plus concerns: `FaceSelection`/`Selection`/`Standing`, `Refusal` (its `impl` now split into two blocks separated by trait impls), `DeleteAffordance`, `SessionOp` (a ~250-line enum), `OpOutcome`, `Gesture`, `DocSession` (24 fields), `BoundsTarget`, `AtRestBadge`, `Landing`, and — since the creation units — datum/profile lowering. It grows one titled section per unit, and no single diff is unreasonable, which is exactly how accumulation stays invisible.

**Specific pressure points named in the reviews:**
- **`Refusal` is becoming a bus** of every layer's vocabulary: delegating arms (`Display(..)`, `Edit(..)`, `Workspace(..)`) beside flat session-local arms, growing roughly one arm per unit, with the rank ladder as a second hand-maintained axis. The creation units also began per-seat wrong-kind arms (being unified in a fix pass), and GAUTH-4/-5 will want body and edge seats.
- **The mid-gesture guard is a convention, not a property**: `if self.gesture.is_some()` now appears 13+ times; a table (or type) of gesture-safe ops would make the next copy unnecessary.
- **Recourse/wording homes have three shapes**: composing fns (`affordance()`, `exists_wording()`, `offer_wording()`), a const (removed again in a fix pass), and plain `Display` arms. The family deserves one shape.
- **The lowering layer is separable today**: the creation units' spec payloads and lowering fns (`DatumSpec`, `ProfileShape`, `datum_node`, `loop_program`) hold no session state, and `revolvetool.rs` already shows unit vocabulary living in its own module.

**What this issue asks for:** a design conversation on the split (which of these concerns get their own modules, what `Refusal`'s delegation discipline is, whether gesture-safety becomes data), ideally ratified before GAUTH-4/-5 add their sections — not a unilateral refactor inside any unit.
