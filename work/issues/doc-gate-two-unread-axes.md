## From GitHub issue 1317

Opened 2026-08-31; 0 comments.

Two axes `scripts/doc-gate.sh` still cannot read after QA-8's pass 3 (PR #1313). Both are disclosed at the site in that script's header and neither is scheduled; this issue is the schedule they owe.

## (a) A broken intra-doc link INSIDE a `not(feature)` half

Pass 3 documents each root that carries a `#[cfg(not(feature = ...))]` half at `--no-default-features`, but runs it with `rustdoc::broken_intra_doc_links` allowed. The reason is measured, not aesthetic: with the feature off, prose that links into the feature-gated half cannot resolve, and on 2026-08-31 a `-D warnings` pass 3 reddened **15 correct link sites** — 13 in `geom-core` over five identifiers (`Interval`, `DualInterval`, `Probe`, `start_recording`, `take_samples`, across `dual.rs`, `k_stats.rs`, `real.rs`) and 2 in `topo`'s boolean prose (`SweepStrategy::Idealized`, `boolean/mod.rs:27` and `boolean/reduce.rs:18`). Those are correct under the gate's primary selection, and a gate that reds on correct prose is one people route around.

What that leaves uncovered: a link inside a `not(feature)` half that is *genuinely* broken is reported by nothing, on any tier. Every other rustdoc lint does now read those halves.

The question this owes an answer to is whether rustdoc can distinguish "unresolvable because the other half is not compiled" from "unresolvable because the target does not exist" — it cannot today by flag alone. Candidate answers: a differential run (collect the allowed-lint set at `--all-features` and at `--no-default-features` and red only on links absent from both), which is a second instrument rather than a flag; or accepting the hole permanently and saying so once rather than at each reader.

Per-root deny lists were considered and rejected in QA-8: they make the lint set a function of which crate currently has cross-half prose, so the first correct cross-half link written in `mesh` reds for being correct.

## (b) `#[cfg(not(debug_assertions))]` — the profile axis

`cargo doc` runs the dev profile, so `debug_assertions` is ON in all three of the gate's passes and every `not(debug_assertions)` half is compiled out of all of them. No feature selection reaches it; it is the same shape as the feature axis one profile over.

Swept 2026-08-31: **16 sites**, in `crates/geom-core/src/spline/knots.rs` (1), `crates/topo/src/review_d18.rs` (12) and `crates/topo/src/review_m1_pr2/release_corruption.rs` (3). Every one is a statement or expression block rather than a documented item, so the axis is **latent** — there is no prose behind it today to be unread. It is filed because latency is not coverage: the next one arrives silently.

The cost question, which is why QA-8 did not take it on the gate's own authority: covering it means a `--release` doc pass. That is a fourth full compilation under a third fingerprint set, on the `fmt` job that F6 of `docs/CI-MINUTES-2026-08.md` already fought back inside 2 billed minutes and that pass 3 has now made doubtful again. Measuring that pass before adding it is the work, not adding it.
