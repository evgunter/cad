## The rule this is about

This repo's standing convention is that **the layer that raised a failure
names it** — a consumer renders a payload through the payload's own
`Display`, and never composes a sentence about somebody else's refusal.
`viewer::session::Refusal` follows it: every arm forwards to its payload,
and the two arms that cannot (`ParseError`, now `HitTestError`) say so at
the site and point here.

Where a type has no `Display`, the consumer's only honest option is a
debug rendering — `{error:?}` — and that is what several user-visible
surfaces currently show. A `Debug` rendering in a status line is not a
message to a person; it is a struct dump that happens to be printable.

## The class

Reported as an instance in #1106 (`HitTestError`), swept by R2 into the

**`editor-core`**

**`viewer`**
- `CameraError` — reaches the status line through `PickError::Camera` and
  through `ViewerApp`'s projection/framing paths.
- `CameraOpError`
- `SceneError` — status line, `format!("scene: {error:?}")`.
- `SceneDocError`
- `StartupError` — the process's exit message.
- `IdMapError`, `PickIndexError` — added by GUI-2; `PickIndexError`
  reaches the status line as `format!("pick index: {error:?}")`.
- `ReplayError`

Not a complete census of the workspace — it is the set two reviewers'
sweeps over one unit's touched surface turned up. Whoever takes this
should re-sweep rather than trust the list: the pattern is a public error
enum with no `impl Display`, and the interesting subset is the one whose
values reach a string a person reads.

## What "done" looks like

`impl Display` on each, stating what happened in the vocabulary of the
layer that raised it, plus `impl core::error::Error` where it is missing.
Then delete the debug renderings at the consumer sites and the comments
that explain why they are there — those comments name this issue, so they
are the thread to pull.

Cited from:
- `crates/viewer/src/pick.rs` — `PickError`'s `Display`.
- `crates/viewer/src/app.rs` — the `scene:` / `pick index:` status lines.

## Why it was not done in #1106

`HitTestError` lives in `editor-core/src/resolve/`, which GUI-2's spec
fences: two extensions were already argued there and a third edit for a
`Display` impl is the wrong trade inside one unit. The viewer-side types
are the same shape of work and belong with it rather than scattered.
