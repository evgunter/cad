## What

`demos/tour/src/teapot.rs:1193` and `:1227` run two `walls::wall`
probes (walls 2 and 3 — the handle union and the spout union) from
inside `pub fn stops(tol)` (`:628`), whose only caller is the render
walk at `main.rs:679`. So they still execute only when something
builds the stop list, which nothing in the test suite does.

`#1434` closed the shape it named — `lily::wall_probes` and
`klein::wall_probes` are both driven by the suite now — but it closed
it for the walls that live in a `wall_probes` function. These two do
not, and they were not in that issue's scope. The CI row
(`.github/workflows/ci.yml:3198`, *"demos tour suite (the #99 ε pin +
the tour's own probes)"*) still promises more than the suite executes.

## Finding

Found by the lane that closed `#1434`'s two halves, which checked
whether the row's name was earned once both landed and found it was
not yet.

The fix has the same shape as the two that landed: an in-bin
`#[cfg(test)]` test driving the probes. It is NOT a copy of them,
because these probes are not separable from `stops()` — the walls sit
mid-way through building the stop list and read bodies that the stop
construction makes. Either the wall pair lifts into its own
`wall_probes`-shaped function that both `stops()` and a test can call,
or the test drives `stops()` itself and pays for building the whole
teapot stop list. Which of those is right is the row's first question,
not a settled matter.

**Not in this row, and deliberately:** whether the CI row's NAME should
change. `.github/workflows/` is unowned ground per `plan.md` — "a row
landing on it is a fence to be drawn, in the same PR that mints the
row" — and this row is about the coverage, not the name. If the walls
all run, the name is earned and nothing there needs touching.

## Closed by the lift (2026-09-15, PR 2626)

Both teapot walls live in `teapot::wall_probes(&Evaluation<f64>, &Recipe)`,
which `stops()` calls and an in-bin `#[cfg(test)]` row drives. The row's
first question — lift a helper or drive `stops()` — is settled as **lift**,
and the complication the row expected did not survive contact: the probes
read *nothing* `stops()` builds. Each argument is a `join_outcome(&ev,
r.<union>)`, an `&Evaluation<f64>` plus a `RecipeNodeId`, which is the
parameter shape every other helper in the file already takes.

They do not take lily's and klein's `wall_probes(tol)` signature, and the
scene's own comment says why: *"the payload the caption quotes and the
payload the probe pins cannot be two different measurements."* A
self-contained `wall_probes(tol)` would evaluate the document a second
time, so the panel's note would quote a different evaluation from the one
the probe pinned.

**The class had a second member and this unit closed it rather than
filing it.** `torusvessel`'s wall 1 — the sectioned vessel's rim — was
also driven only by the render walk, in a file that carried no
`#[cfg(test)]` at all. It takes `wall_probes(tol)` outright, because its
operands are built immediately above the probe and read by nothing after
it. Two signatures for one class, with the reason written at both sites
and each naming the other as the counter-case.

**The row's framing was wrong in a way worth keeping.** The walls were
not unexecuted everywhere: `render.yml`'s `cargo run --release -- ../out`
and the k-lint gate's tour step both attempted them. What they lacked was
a driver under the **command the CI row names** (`cd demos/tour && cargo
test --release --features interval`), which is the command a reader of
that row believes covers them. That is the defect, and the promise is now
earned — the gate's own step lists all four scenes that call
`walls::wall`, and the bin suite went 31 → 33 rows.

**Red-first receipts, both executed.** Flipping the teapot's pinned

pinned refusal text fails at the "refuses but NOT with the refusal it

**Deliberately not taken:** the step-export frontier pins

it *is* the render walk by construction rather than a probe that could be
lifted out of one. Recorded as a stated blind spot, not a row.
