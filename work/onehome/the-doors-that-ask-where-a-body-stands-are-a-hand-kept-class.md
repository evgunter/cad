Filed by the ONEROUND orchestrator (2026-11-19) from the two designers who weighed the session box's reach for Ev (`work/oneround/the-session-box-reach-misses-a-curved-faces-bulge.md`). Both raised it and both moved it out of that question.

**What.** A value stood somewhere by a map is asked the session box at the door that stands it (`Framed::asked_where_it_stands`, `crates/editor-core/src/eval/framed.rs`). Which doors ask is a class kept by hand: the module doc of `framed.rs` argues that a result inside its operand's hull stands where the box admitted the operand (the cube is convex), and lists the doors whose result can leave that hull (a placement, a sketch frame, a lift, a mirror). Every new operation has to classify itself against that paragraph, and nothing checks that it did. Both designers report, from PR 7088's body, that the list missed the mirror once; that was not re-checked for this row.

**The argument is sound only once "admitted" means the whole region is in the cube.** Today the box reads a body's vertices and edges, so the header states the hull argument of a reach the box did not read. The session-box question to Ev makes it true; if that lands, this row is about the list alone.

**Candidates, neither chosen.** (a) The only way to make a value stood by a map is a constructor that asks, which retires the list and the paragraph for one more read per operation under a frame. (b) A gate on the class. Both designers leaned to (a) and both were unsure, for one reason: its cost on the box-scalar lanes is unmeasured, and they report PR 7088 as saying the placing door's ask starved `m10_3_driver_interval`'s `a_terminal_sliver_refuses_naming_its_predicate_and_is_not_refined` (also not re-checked). Measure that first.
