## Re-derived (2026-09-15, lane A)

**VERDICT: REPRODUCES, with the count up 13 → 14 and one secondary claim
now false.** The duplication is live; the collapse is if anything easier
than the row implies, because the fourteen bodies are now byte-identical.

### The population: fourteen, not thirteen

`grep -rn 'fn every_suite_file_is_aggregated' --include='*.rs'` returns
**14**, one per crate: `bvh`, `editor-core`, `geom`, `geom-brep`,
`geom-core`, `mesh`, `profile`, `step-export`, `step-import`, `stl`,
`sweep`, `topo`, `verbs`, `viewer` — each in that crate's
`tests/all.rs`. A copy has been added since the row was written; the row
says thirteen four times, including in its title.

### The fourteen bodies are now IDENTICAL, byte for byte

I hashed each guard from its `fn` line to its closing brace
(`awk` extract → `md5sum`): **all fourteen hash to the same value**.
Each is five lines:

```rust
fn every_suite_file_is_aggregated() {
    let tests = test_utils::source::crate_dir(env!("CARGO_MANIFEST_DIR")).join("tests");
    let violations = test_utils::source::aggregation_violations(&tests, include_str!("all.rs"));
    assert!(violations.is_empty(), "{}", violations.join("\n"));
}
```

with the same doc comment above it. `D61`'s narrowing has gone further
than the row records: the shared home is no longer just the lexer but
`test_utils::source::aggregation_violations`, which owns *"the walk, the
three checks and the argument for each"* (the doc comment's own words).
**What is left is exactly what the row says is left — that there are
fourteen of them** — and it is now purely a call-site count, five lines
each, with nothing crate-specific in any of them but `CARGO_MANIFEST_DIR`
and `include_str!`. That makes this a smaller unit than the row implies,
not a larger one.

### The `crates/test-utils/tests/` rider: the claim is now FALSE as written

The row says `crates/test-utils/tests/` *"is the only workspace member's
test directory with no `all.rs` and no `autotests = false`"*. Enumerating
every workspace member with a `tests/` directory
(`crates/*/Cargo.toml` + `ls`): sixteen members carry both
`autotests = false` and `tests/all.rs`; **two** carry neither —
`crates/test-utils/` and `crates/pncad-py/`.

The claim survives if narrowed to **Rust** test directories:
`crates/pncad-py/tests/` holds only `.py` files and `bench_scene.py`, no
Rust test target at all, so it is not a fourteenth-copy risk. The row
should say *"the only member with RUST tests and no `all.rs`"*.
`crates/test-utils/tests/` still holds exactly one file,
`reader_census.rs`, and `crates/test-utils/Cargo.toml` still has no
`autotests` key — so the substance (opting it in means a fourteenth —
now **fifteenth** — copy, or a stated hole) is intact.

### A fifteenth aggregating crate that deliberately has no copy

`crates/pncad/` has `autotests = false` and `tests/all.rs` but **no**
`every_suite_file_is_aggregated`. That is deliberate and documented in
its own header — *"**No aggregation guard here, and why.** … This
`tests/` directory holds ONE `.rs` file — this one — so there is no set to
check"* — with the guard that keeps the sentence true named:
`crates/bvh/tests/aggregator_headers.rs`'s
`a_non_aggregating_tests_directory_holds_one_suite_file`. Not a
fifteenth member and not a hole; recorded so the next taker does not
count it as either.

### `scripts/gates/test-aggregation.sh` is still there

Still present, still covering *"a member that never opted in at all —
which is the hole this check exists for"* in its own words. The row's
sentence that it *"covers a member that never opted in"* holds.

### What my sweep could not match

A copy under a different NAME doing the same job — I matched the literal
`every_suite_file_is_aggregated`, so a crate that spelled its guard
differently would not appear. I cross-checked with
`grep -rln 'suite_files'` (12 files) and `grep -rn 'autotests'` (16
manifests) and reconciled every difference above, so the residual risk is
a guard that uses neither `suite_files` nor
`aggregation_violations` nor that name — which would also not be a copy
of this one.

## Corrected and taken by TINT-3 (2026-09-15)

Three claims above are false as written. They are corrected here rather
than edited out, because the body is also the record of what the row
looked like when it was minted.

### 1. The count is FIFTEEN, not thirteen and not fourteen

The title said thirteen and the body says it four times; lane A's
re-derivation earlier the same day said fourteen. On the merge base of
the fix (`origin/tint/2-stand-down-channel`, and on `origin/main` at the
same hour) `git grep -l 'fn every_suite_file_is_aggregated' -- '*.rs'`
returns **fifteen**: the fourteen lane A listed plus
`crates/test-utils/tests/all.rs`. All fifteen `fn` bodies hash
identical (`awk` from the `fn` line to the closing brace → `md5sum`,
one hash); the doc comment above them differs in `test-utils`' copy by
line wrapping only.

**The number is not the point and should not be re-pinned.** It moved
three times in eighteen days because a copy is what a new aggregating
crate pastes. What the fix removes is the pasting, not a count.

### 2. The `crates/test-utils/tests/` rider is DONE, not pending

The row was written when opting `test-utils` in would have cost a
fourteenth copy or a stated hole. It has since been opted in —
`crates/test-utils/tests/all.rs` exists, mounts three suites, and
carried the fifteenth copy — so the rider was resolved by paying the
cost the row wanted avoided, and TINT-3 removes what it cost.

Lane A's narrowing of the *"only member with no `all.rs` and no
`autotests = false`"* claim still stands as re-derived, and narrows
once more: **`crates/pncad-py/` is now the only one**, and only because
its `tests/` holds Python, no Rust test target at all.

### 3. `crates/pncad/` is not a hole and must not be "fixed"

It has `autotests = false` and `tests/all.rs` and deliberately no row:
its `tests/` holds one file, its header says why, and
`crates/bvh/tests/aggregator_headers.rs`'s
`a_non_aggregating_tests_directory_holds_one_suite_file` is what keeps
that sentence true. TINT-3 left it alone.

### What TINT-3 did NOT close

**Nothing checks that an aggregating crate HAS the row.** A sixteenth
crate added tomorrow that mounts suites and never invokes
`test_utils::every_suite_file_is_aggregated!()` is silent, exactly as a
crate that never pasted the five lines was silent before. The collapse
neither closes that hole nor widens it, and the macro's own doc comment
says so where a reader of the mechanism will meet it.
