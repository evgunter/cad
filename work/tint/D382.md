## Re-derived (2026-09-15, lane A)

### The population: fourteen, not thirteen

`grep -rn 'fn every_suite_file_is_aggregated' --include='*.rs'` returns
**14**, one per crate: `bvh`, `editor-core`, `geom`, `geom-brep`,
`geom-core`, `mesh`, `profile`, `step-export`, `step-import`, `stl`,
`sweep`, `topo`, `verbs`, `viewer` — each in that crate's
`tests/all.rs`. A copy has been added since the row was written; the row
says thirteen four times, including in its title.

### The fourteen bodies are now IDENTICAL, byte for byte

I hashed each guard from its `fn` line to its closing brace
(`awk` extract → `md5sum`): **all fourteen hash to the same value**.
Each is five lines:

```rust
fn every_suite_file_is_aggregated() {
    let tests = test_utils::source::crate_dir(env!("CARGO_MANIFEST_DIR")).join("tests");
    let violations = test_utils::source::aggregation_violations(&tests, include_str!("all.rs"));
    assert!(violations.is_empty(), "{}", violations.join("\n"));
}
```

with the same doc comment above it. `D61`'s narrowing has gone further
than the row records: the shared home is no longer just the lexer but
`test_utils::source::aggregation_violations`, which owns *"the walk, the
three checks and the argument for each"* (the doc comment's own words).
**What is left is exactly what the row says is left — that there are
fourteen of them** — and it is now purely a call-site count, five lines
each, with nothing crate-specific in any of them but `CARGO_MANIFEST_DIR`
and `include_str!`. That makes this a smaller unit than the row implies,
not a larger one.

### The `crates/test-utils/tests/` rider: the claim is now FALSE as written

test directory with no `all.rs` and no `autotests = false`"*. Enumerating
every workspace member with a `tests/` directory

`autotests = false` and `tests/all.rs`; **two** carry neither —
`crates/test-utils/` and `crates/pncad-py/`.

The claim survives if narrowed to **Rust** test directories:

`crates/test-utils/tests/` still holds exactly one file,

## Closed — TINT-3, PR #2680 (2026-09-15)

**Fifteen byte-identical bodies became one macro**,
`test_utils::every_suite_file_is_aggregated!()`, sited beside
`aggregation_violations` whose call-site half it is. The generated `fn`
keeps its name, so the PASS list, `--filter` args and all six live prose
citers stay true unchanged.

**The count was fifteen, not this row's thirteen or the re-derivation's
fourteen.** `crates/test-utils/tests/all.rs` landed between lane A's
count and the fix, carrying the fifteenth — which is **this row's own
`test-utils` rider, resolved by paying exactly the cost the row wanted
avoided.** Title corrected; it said thirteen and asked to "opt test-utils
in", both stale.

**The mechanism was measured before it was built**, per
`work/tint/process-observations.md` observation 2. `env!("CARGO_MANIFEST_DIR")`
and `include_str!("all.rs")` inside an exported macro both resolve at the
**invocation** site — established with a two-crate probe, a negative
control (the definition-site `all.rs` deleted and the tree rebuilt
clean), and a spelling control (bare vs `::core::`-qualified), then
independently re-confirmed by the review with its own probe. Had either
resolved at the definition site, all fifteen rows would have checked
`test-utils`' tree instead of their own.

**Proved by mutation in a crate that is not `test-utils`** — deliberately,
because the decisive evidence is the plant's own crate going red with its
own counts. All three of the guard's checks are now evidenced through the
macro: an unaggregated suite file, an orphan mount, and a `mod` declared
inside a suite.

## What the collapse cost, and what closed it

`crates/test-utils/tests/reader_census.rs` had been detecting each
aggregating `all.rs` as a source reader **by a margin of exactly one**
`.rs"` literal — the one `include_str!("all.rs")` supplied. Moving that
token into a macro takes fourteen of fifteen aggregators to zero margin,
so two detectors had to move. The review adjudicated that move a
**correction, not a silencing**: a `||`-joined needle list widens
monotonically and cannot silence, the files still genuinely read Rust
source through the macro, and the silencing option — deleting the fifteen
ledger lines — was available and not taken.

**But the collapse traded fifteen independently-checked facts for one.**
Before, reverting any single `all.rs` red'd that file; after, the claim
that the macro reaches the shared lexer has one subject, and
`source.rs` is dispositioned `Home`, which that row filters out — so a
rewritten macro body left **all sixteen rows green**. That is inherent to
15→1 and does not make the change wrong, but it was undisclosed until
the review found it.

It is now disclosed AND closed: `the_aggregation_row_macro_reaches_the_shared_lexer`
reads the macro body and asserts it still calls `source::crate_dir` and
`source::aggregation_violations` — measured to red on exactly that
mutation and nothing else. The honest statement kept at the site: one
check with one subject is weaker than fifteen with fifteen, and that is
what the collapse is bought with. **Worth it here because the fifteen
were byte-identical; not worth it where copies differ.**

**The unit also minted a small instance of its own class and closed it.**
The census needed the macro's name as a string in two places, in two
spellings, checked against nothing. Now `aggregation_row_macro!()` is the
single source feeding both, held to the real macro by
`the_aggregation_row_needle_names_a_macro_that_exists`.

## What it does NOT enforce

**Nothing checks that a crate HAS the row.** A sixteenth aggregating
crate that never invokes the macro is silent — the same hole the fifteen
copies had, neither closed nor widened. Named at the macro, with the
neighbouring ground that does not cover it
(`scripts/gates/test-aggregation.sh` is the opt-in, not the row;
`crates/bvh/tests/aggregator_headers.rs`'s
`a_non_aggregating_tests_directory_holds_one_suite_file` is about a crate
that mounts nothing).

**The invocation-site measurement is unguarded, with the reason written
at the claim site** per `docs/prompts/reviewer-style-lane.md` Q6 / #651.
No guard is possible: any guard would be the comparison the macro already
is, and would flip with it. The reason it is safe is not that the failure
would be loud — it would be silent — but that invocation-site resolution
is part of Rust's stability promise, so the flip is a breaking language
change and a scheduled re-measure buys nothing `rustc`'s release process
does not.
