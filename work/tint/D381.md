## What

**`RecipeEditRef::ForeignNode` is unpinned at both mid-evaluation doors.** `editor-core`'s selection and declare doors resolve authored names through one shared ladder (`eval/wire.rs`'s `mod ladder`), whose rung 1 splits a missing minting node into `NodeDeleted` (id below the mint counter) and `ForeignNode` (id at or above it). `m6_5_selection_refusals.rs` and `m4_pr5_declare.rs` pin every other arm of that ladder and **neither pins `ForeignNode`**; the crate's only pin of it, `m4_pr4_resolve.rs:423`, is the *whole-evaluation* resolve door, which is a different ladder. The arm is reachable only across documents — the edit door refuses never-existed ids before evaluation — which is why it was left unpinned, not why it should stay so: #670 collapsed the two doors onto one implementation, so one fixture now covers both. Disclosed by that PR and never rowed

## Re-derived (2026-09-15, lane A)

**VERDICT: REPRODUCES** — exactly as filed; only the line number rotted.

**The arm exists and the ladder is unchanged.**
`RecipeEditRef::ForeignNode` is declared in
`crates/editor-core/src/resolve/mod.rs` and constructed there at one
site; `crates/editor-core/src/eval/wire.rs` still carries `mod ladder`
and still documents rung 1 in the words the row paraphrases:

> *"1. [`ladder::live`] — the minting node must still be in the document.
> Ids are never reused, so an id below the mint counter was DELETED and
> one at/above it was never this document's (`ForeignNode`). This rung
> outranks every later refusal, including a door's own …"*

**The crate's only pin of `ForeignNode` is still the whole-evaluation
resolve door.** `grep -rn 'ForeignNode' --include='*.rs' crates/` returns
five hits and exactly one is a test:
`crates/editor-core/tests/m4_pr4_resolve.rs` (the row's `:423`, now
`:424` — line rot, the pin itself unmoved). The other four are the two
`resolve/mod.rs` sites and the `wire.rs` doc rung.

**Both mid-evaluation doors still pin every other arm and not this one.**
`crates/editor-core/tests/m6_5_selection_refusals.rs` pins `NodeDeleted`
(`matches!(edit, RecipeEditRef::NodeDeleted { node } if *node == spare_id)`)
and `crates/editor-core/tests/m4_pr5_declare.rs` pins the derived
`NodeDeleted` edit twice, including the key assertion
`k.contains("DeclareResolve") && k.contains("NodeGone") && k.contains("NodeDeleted")`.
Neither file contains the string `ForeignNode` anywhere.

So rung 1's two-way split is pinned on one side only, at both doors —
which is the row, unchanged. #670's collapse of the two doors onto one
implementation is still what makes one fixture cover both: `mod ladder`
is one module and both doors reach it.

**Recommendation: keep open, and it is small.** One fixture that mints a
node id at or above the document's mint counter and drives it through
either door.

**What I could not settle by reading:** whether such a fixture is
*constructible* through the test crate's public doors — the row says the
arm is *"reachable only across documents — the edit door refuses
never-existed ids before evaluation"*, and whether the test crate can
stage a cross-document id without reaching past the API is a question for
the lane that writes it, not for a grep.
