## Finding

### S163. What the F3 sweep left open in `scripts/gates/` — four members, one row

Raised by lane **F-g** while closing S63 and S157, and **grown by that PR's style and adversarial reviews** — the members with numbers attached are the ones those reviews added. One row (**D109**), because each is a disclosed blind spot of the same sweep and a reader who takes one should see the others.

**(b) One gate is off the shared reader on purpose, and it is the one that decides the reader's interface.** `probe-suite-census.sh`'s probe-gate matcher looks for `#[cfg(feature = "probe")]` — **its needle contains a string literal**, so the code-only view would blank exactly what it wants. What it wants is `code_and_literals` (comments stripped, literals KEPT) — **one of `test_utils::source`'s three views, not a fourth** — and that is the one of the three `gate_rust_code` does not build. Its matcher is anchored at column zero instead, and it carries a prose fixture because of that. **#849's first record claimed no gate here greps for a string literal**, which was the whole argument for building one view; the argument still holds for the gates converted to the code-only view, but as a statement about them, not about the directory. (Note: `probe-suite-census.sh` and `gate-roster.sh` are outside this track's fence; `D208` is the row for the *description* of this view in `lib.sh`, and this member is the row for *building* it in the shell reader.)

**(c) The shared reader is a lexer, and says so.** Nested block comments (Rust allows them; the first `*/` closes here), `macro_rules!` bodies, `include!`d text, and anything behind a `#[cfg]` other than the `test` skip are all read as ordinary code. Only a **test-only** attribute may exclude — `any(test, …)` and `not(test)` are both scanned, since `any(debug_assertions, test, …)` is every debug build (`topo`'s `test_support_impl` is exactly that, and an earlier draft skipped it). An ALL-CAPS operand (`SOME_CONST * SOME_CONST`) and an indexed square (`v[i] * v[i]`) are both invisible to the square matcher, the first deliberately (the ALL-CAPS population here is `usize` sizing) and the second not.

**(d) 6 of 82 `gate_error` call sites in `scripts/gates/` are reached by no self-test case, and every one of the six is outside this track's fence**, re-derived 2026-09-03 by instrumenting `gate_error` with `BASH_SOURCE`/`BASH_LINENO` and tracing all sixteen `--selftest` runs. Re-derive it the same way rather than trusting this number: the population grows every time a gate gains a guard, and the count above is a reading, not a register. The declared population is `grep -nE '(^|[[:space:];&|])gate_error "' scripts/gates/*.sh` less the definition line — say the pattern with the count, because a `gate_error` inside a `printf` is not a call site and an earlier reading of this member counted one.

The six are `gate-roster.sh`'s missing-local-half, empty-roster and *"loops the gates but never runs one"* guards, and `probe-suite-census.sh`'s nested-suite diagnosis (the one inside the command substitution that motivated the stdout→stderr move), its missing-`SWEEP_SCRIPT` guard and its missing-`ci.yml` guard. Both files sit on retired Track `J`'s unowned ground, so their fixtures are a row to be drawn there, not work this track can take.

**Three in-fence guards were recorded here as UNREACHABLE, and all three were reachable.** Each is now planted, and the correction is worth more than the fixtures: every one of the three arguments generalised a property of the tree today into a property of the guard.

- `lib.sh`'s *"defines no `gate_selftest`"* — the argument was that every gate defines one and a gate that did not would red `gate-roster.sh`. That is an argument about the DIRECTORY. The guard's subject is anything that sources `lib.sh`, and a six-line scratch script reaches it; the case lives in `gate_selftest_clean`, so every caller carries it.
- `signed-zero-one-home.sh`'s *"no `.rs` files under the scanned directories"* — the domination argument assumed `[ -f X ]` implies `find … -type f` sees `X`. It does not: `gate_require_file` follows a symlink and `find … -type f` does not, so a home file symlinked to a real `.rs` outside `SCAN_DIRS` clears the first guard and leaves the scan empty. Planted as `plant_home_symlinked_out_of_the_scan`. **The predicate mismatch is left in place deliberately** — the two spellings ask different questions, and the reasoning for not aligning either way is at that planter.
- `interval-square-allowlist.sh`'s *"every source … is test-only"* — it needs no cyclic module graph. The reading that called it unreachable was an argument about the tree, not about the guard: a handful of sources that exclude each other reaches it, and the guard is planted. The mechanism the first plant used — a declaration excluding its own declarer, because the exclusion was `dir/name.rs` pasted from the declaring file's directory with no check that the target differed — is gone with the textual resolution it belonged to (`gate-mod-path-resolved-textually`, PR 2033: `#[path]` wins, a crate root or `mod.rs` resolves to the sibling and any other declarer into its own directory, and a declaration naming its own file excludes nothing). The guard is now reached by `plant_every_source_excluded_by_a_sibling`, two crate roots in one directory each declaring a test module of the other's name.

**`lib.sh` says a guard never shown to fire is not a guard**, and the sentence resolves per line into *owes a fixture* or *owes a decision*. Every in-fence line resolved to the first; none resolved to the second, and the reading that said otherwise had converted three owed fixtures into three owed decisions. The count is here rather than a caveat so that it can be worked down.

**The class, swept.** Two shapes, both derived from the corrections above, hit list and blind spot in the closing PR's body: `[ -f ]` deciding about a file whose scan set comes from `find … -type f` (four in-fence members), and a path built by textual concatenation where `rustc` resolves it (one in-fence member).

**(e) The real-scan cost went from ~4.5 s to ~48 s across the six converted gates**, measured on the F-g lane container (a shared box at load average ~12, not a runner): 5.9 / 6.2 / 6.0 / 9.6 / 11.3 / 9.5 s against 0.5–1.0 s each before, and both halves of CI run every gate twice (`--selftest` then the gate). **On the hosted runner the whole `discipline` job is 30 s against a 23 s pre-change baseline and every gate step is 0–1 s** (runs `32439375293` and `32388258102`), so nothing is at risk today — the number is here because a tenfold aggregate change should be findable by the next person rather than discovered.

## Landed (2026-09-06)

All four members, on `gates/d109-reader-blind-spots`. What each one
settled, in the terms the finding above set:

**(b)** `lib.sh`'s `gate_rust_code` gained `--keep-literals` — the same
lexer emitting literals as written — which is `code_and_literals`, the
third of `test_utils::source`'s three views and not a fourth.
`probe-suite-census.sh` reads its `crates/*/tests` through it and its
predicate left the whole-line anchors: a gate line with a trailing
comment is counted now, one inside a `/* */` block is not, and both are
fixtures. The clean fixture's prose file became an ordinary string
literal spelling the attribute, which the view keeps and the needle
cannot match (Rust escapes its inner quotes). **What keeping literals
costs**: a RAW literal spelling the attribute verbatim IS counted, which
is the one direction the view cannot close.

**(c)** Nested block comments are FIXED — `lib.sh` counts depth to any
depth and ACROSS LINES, as rustc does and as `test_utils::source`
already did. **The depth is a state, not a per-line tally**, and the
first cut of this got that wrong: an opener was counted only when a
closer sat on the SAME line, so `/* outer` / `/* inner` / `*/` — the
ordinary way a nested comment is written — left the depth at one, the
next `*/` ended the outer comment early, and the attribute below it was
code again. Both shapes are planted, and each goes red against its own
mutation of the reader (the one-line inner against nesting backed out,
the multi-line inner against the per-line tally). The other three blind
spots are recorded and accepted, one paragraph each in the header with
what it is blind to and why: `macro_rules!` bodies (read as written,
never as expanded; the fix is expanding Rust), `include!`d text (not
followed, because the caller's file set is the subject and the count a
gate prints must name what it read), non-`test` `#[cfg]` (scanned as
live code — the cry-wolf direction, which cannot go blind) — and a
fourth found while stating them: an unterminated `/*` swallows the rest
of its file silently, accepted because `rustc` refuses such a file, so
only source that does not compile can carry one. The indexed square
`v[i] * v[i]` is
NOT this reader's blind spot: the view carries it as written, and the
gap is in the square matcher's needle, stated in
`interval-square-allowlist.sh`, which another lane had open.

**(d) Re-derived, and the reading was low.** Pattern:
`grep -nE '(^|[[:space:];&|])gate_error "' scripts/gates/*.sh` (the
definition line does not match it). At `origin/main` fcbd8942e: **105
sites, 12 reached by no `--selftest` case** — the six this row names,
planted here, and six more in `viewer-module-kinds.sh`, filed as
`viewer-module-kinds-six-unreached-guards`. After this branch: 106
sites, 6 unreached, all in that gate.

**The 2026-09-03 method under-reports and the correction is worth more
than the count.** `BASH_LINENO` at a `gate_error` inside a command
substitution names the ENCLOSING FUNCTION CALL's line — bash resets the
call stack in the subshell — so a line-only trace reports such a site
unreached however many fixtures fire it. This row's own census guard is
that shape. Trace the MESSAGE too and match a site by all of its literal
fragments in one message; any-of scores a site reached off a fragment
two messages share. `lib.sh`'s `gate_selftest_clean` note now says so.

**(e) Re-measured, and the old reading does not reproduce here.** Best
of three, 2026-09-06, 4-core container at load average ~0.8, `mawk`.
Every gate 0.02–0.52 s before and after, unmoved to two decimal places,
except `probe-suite-census.sh` — and **the cost lands on every mode
that reads the census, not only on its real pass**, because
