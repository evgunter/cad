## What

`scripts/gates/*.sh` carries readings of the tree — census counts,
sample counts, timings — that nothing re-derives, and one of them
carries a live claim about today's tree. Convert the live one to an
executable home the way `tools/tess-lint/tests/baseline_census.rs`
did for the face-identity census: state the sweep's definition beside
its result, re-derive it on every run, and leave the prose pointing
rather than counting.

**The file is contended.** A lane is converting `bounds-allowlist.sh`
onto the shared reader and writing self-test fixtures; sequence this
row after it.

## Was

bullet ordered. `#783`'s `--include=*.rs` excluded the whole directory,

## Finding

### The live one: `interval-square-allowlist.sh`'s five-spelling scan

Its header block argues, in the present tense, that the five shapes the
matcher structurally cannot see are not live — the paragraph beginning
*"NONE OF THESE IS LIVE, AND A CLEAN RUN OF THIS GATE IS NOT WHY"*. The
evidence is a scan run once: a two-statement `let`-binding pass over
**52,471 production statements**, `0` hits for the parenthesized and
nested forms, `21 + 3` candidates for the three-factor and
two-statement forms, each dispositioned in prose. Nothing re-runs any
of it, nothing dates it, and the claim it supports is about the tree as
it is now rather than as it was. That is exactly the shape `C15` and
`D201` were pointed away from: a census transcribed into prose.

The same file's backend paragraph carries a second, weaker instance —
`0` widening cases in **3,000,000** samples over `|x|` in `[1e-60,
1e60]`, with the witness `x = 2^-481*1.5`. This one **discloses its own
status** (*"evidence about the sampled window"*) and says the witness
is re-runnable in a line, which is most of the honest work; what is
missing is that nothing re-runs it. Weaker instance, same cure.

### The stale one: `bounds-allowlist.sh`'s KNOWN GAP 3

The gap paragraph sizes itself: *"the ~49 USES in
`profile/src/path/{family,program}.rs`"* of the `ArcCarrierScalar`
alias. Re-derived on this branch it is **52** (27 in `family.rs`, 25 in
`program.rs`; 63 repo-wide). The figure sizes a disclosed gap rather
than gating anything, so the drift costs nothing today — it is in this
row because the count is a reading of a live population with no home,
and the next reader has no way to know which era the `~49` belongs to.
Cited by target name (`KNOWN GAP 3`) because the file is being edited.

### What is NOT in this class, and it is worth saying

Two blocks carry dense figures and are **correct as they stand**,
because each says what its numbers are and what re-derives the
invariant instead:

- `test-aggregation.sh`'s bazel-verdict block (`494 of 514 s`, `96%`,
  `249 targets to 12`, `26`) closes with *"Those two figures are the
  record of that event and not claims about today; what this gate
  asserts is the INVARIANT, and it prints the current total rather
  than pinning one."*
- `no-ambient-env.sh`'s `NURBS_PROBE` indictment (`91-sample`,
  `7.9 s -> 19.8 s`) calls itself *"an undated reading of a channel
  this gate has since removed, so there is nothing left to re-take"*.

The class is not "a number in a comment". It is **a reading presented
as current that nothing re-takes**, and the two blocks above are the
disciplined form of the same material.

`lib.sh`'s three implementation-choice timings (`~14 s` vs `~4 s`,
`43 s`, `~8 s`) are readings with no home either, but they justify a
technique rather than assert a state of the tree; a stale one misleads
about cost, not about correctness. Lowest priority of the four.

## Landed (2026-09-06)

On `gates/readings-re-derived`, with `S13`.

**(a) The five-shape scan has an executable home.**
`interval-square-allowlist.sh` runs a second pass over the SAME
statement view its live matcher reads — one read, so the two answers
cannot be about two trees — and counts the candidates of each of the
five spellings `KNOWN GAP 5` names. Three are `grep -P` patterns
(`CENSUS_PAREN_FIRST_RE`, `CENSUS_NESTED_PAREN_RE`,
`CENSUS_THREE_FACTOR_RE`); the fourth is the binding hop
(`two_statement_candidates`), which is two records and so not a regex
over one. `CENSUS_REGISTER` is the disposition of what the pass reads,
`S49`/`probe-suite-census.sh`'s shape: `<shape>|<file>|<fragment>|
<count>|<disposition>`, keyed on a fragment of the site's own statement
text and never a line number. The reds are the register's three — a
MALFORMED entry, an UNREG candidate no entry names, a MISCOUNT in
either direction (`matched 0` is a site that is gone) — plus ABSENT,
an entry whose file has left a scan the rest of the register is still
live for. The header now points at those names and states the census's
own blind spots; it no longer counts.

**What moved, and why.** The prose claimed `21 + 3` candidates over
`52,471` production statements. Neither figure is restated here — that
is this row's own class, and the reading now has a home: run
`scripts/gates/interval-square-allowlist.sh` and its OK line prints the
per-shape counts, and the register beside `CENSUS_REGISTER` names every
site behind them. What is worth recording is the SHAPE of the drift,
because it is the argument for the home: the `21` is not reproducible
from what `KNOWN GAP 5` says the shape IS — "the same product … and no
parentheses anywhere" — and is reachable only by letting the
three-factor pattern's middle run through `+`, `,` or a parenthesis.
Nobody reading `21` could tell which of those it had been. The
two-statement figure reproduces exactly, once the pass follows one
binding hop within a file rather than only to the next statement.

The census also declines to count what branch 1 already sees: an
adjacent repeat (`h * h * h`) is quiet in an allowlisted file on that
file's ratification, so claiming it here would make the gate's own
sentence false for it and would put a NEW adjacent square in such a
file through the census as an unregistered candidate — replacing
`KNOWN GAP 4`'s file-granular ratification with a per-site one for one
spelling. Every wedged factor must therefore differ from the operand,
and a fixture in an allowlisted file pins it.

**(b) The backend paragraph stays prose, with a pointer that resolves.**
The witness is NOT re-run in the self-test, and the reason is the
fence: the claim is about the backend's arithmetic, so re-running it
means compiling `interval-transcendentals`, which a shell gate in a
`discipline` job that invokes no cargo at all cannot do. Nothing in
`crates/interval*` re-runs it either — there is no such crate; the
backend is `interval-transcendentals/` at the workspace root, and its
`tests/certify.rs` and `tests/review_fuzz_exact.rs` sweep the `2^-960`
floor without ever comparing `powi(2)` against `x * x` at the witness.
So the header keeps its status disclosure and gains the two things that
make it checkable by hand: the re-run written out as a `#[test]` in
that crate's OWN public API — `DInterval::point`, `powi`, `lo`/`hi`,
because it is its own workspace and cannot reach geom-core, with the
`2^-481 * 1.5` bit pattern spelled `0x21E0_0000_0000_0000` — and the
home of the floor the derivation rests on, `TWO_PROD_VALID_MIN` in
`interval-transcendentals/src/round.rs`, whose value and `mul_hi`
lemma are what a moved floor would change. The recipe is not a
guess: it was compiled and run against the crate before being written
down, and it passes — `powi(2)` is wider on BOTH sides at the witness
and bit-equal to the plain product at a magnitude above the floor.

**(c) GAP 3's `~49` is already gone**, and nothing was done there. PR
2056 rewrote `bounds-allowlist.sh`'s KNOWN GAP 3, and on this head it
carries no count of the population at all — it reads *"the uses of the
name in profile/src/path/{family,program}.rs (grep it; the count moves
with the files)"*. That is the cure this row asked for, applied by
another lane. `bounds-allowlist.sh` was not edited.

**The residue this row does not close.** `lib.sh`'s three
implementation-choice timings (`~14 s` vs `~4 s`, `43 s`, `~8 s`) are
still readings with no home. The row rated them lowest priority
because they justify a technique rather than assert a state of the
tree, and `lib.sh`'s own text now says so at the site; they stay
disclosed. `D109`(e)'s aggregate gate-cost reading is the same class
and is that row's.

**Fixtures (all in `--selftest`), and every one mutation-proved.** An
undispositioned candidate of each of the four shapes, each written so
the LIVE matcher cannot see it — a fixture the live matcher reds would
prove nothing about the census. The register's own tree, planted FROM
`CENSUS_REGISTER` so every entry finds exactly what it pins. The three
tree mutations — a second candidate under a one-site entry, an entry
whose site is gone, an entry whose file has left the scan — run for a
three-factor entry AND for a binding-hop one, because keyed on entry 0
alone the binding hop's own MISCOUNT and ABSENT paths were reached by
nothing. Both halves of the (file, shape) key, each against a WRITTEN
register whose single entry would wrongly claim the tree's single
candidate if that half were dropped; with the right candidate also in
the tree, dropping the check turns a pass into a MISCOUNT and the case
reds either way, proving nothing. A malformed entry and a `--register`
with no argument, through this gate's own flag. A field-path binding
hop beside the name its unescaped `.` would match as a wildcard. And an
adjacent triple in an allowlisted file, which the census must leave
alone.

**Every `want` is a fragment of the offending LINE**, built from the
register, never a word from the umbrella diagnosis. `lib.sh` warns that
`$want` alone can be satisfied by text the gate prints for another
reason, and this gate is where that happened: `matched 0` and `ABSENT`
both appear in the sentence explaining what those lines MEAN, so either
case was satisfied by any census red at all — including one with the
very check it is about deleted.
