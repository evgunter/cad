`crates/geom-core/tests/review_m0_pr2.rs:26-72` (8 blocks) and
`crates/geom-core/tests/review_m0_pr3.rs:27-48` (3 blocks) open fences
tagged `compile_fail,EXXXX` inside `//!` docs of an integration-test
target. Rustdoc never collects a doctest in a `tests/` target, so these
blocks have never run on any tier. Both file headers already say so
(`review_m0_pr2.rs:20`, `review_m0_pr3.rs:21`), but the
`compile_fail,EXXXX` tag still reads as an executed assertion at the
fence itself. Two of the blocks record one claim (the generic `Real`
compare, `E0369`, once in each file).

Moving them into `geom-core/src` would make them run in the per-PR
`doc-tests` step (`.github/workflows/ci.yml:475-477`). geom-core
already carries about 34 `compile_fail` blocks in `src/`, and each one
is its own rustc invocation. No regression these blocks would have
caught has been recorded since they were written in July 2026, so the
move would add per-PR cost with nothing on the record to pay for it.
`crates/geom-core/src/real.rs:2176-2189` already guards the sealed
`Certifies` contract the same way.

The change: re-tag the eleven fences as `text`, and in each header
replace "kept in `compile_fail` doctest form" with one sentence saying
the blocks record review findings and nothing runs them. If a later
regression shows that one of these properties needs a guard, that
property gets one `compile_fail` block on its own item in `src/`, as
`real.rs` does.

What would close it: no `compile_fail` fence remains under `crates/*/tests/`, and both headers say the claims are unguarded.
