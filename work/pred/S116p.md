## Question

**`MultipleAxisRuns` changed what the kernel promises**, from
*"deferred to M3"* to *"a **permanent** refusal under the ratified
sweeps-vs-voids invariant"*. That rests on an unstated geometric claim
— that every profile with ≥2 disjoint on-axis runs encloses a void when
fully revolved — with no test, no proof, and the reporting agent's own
confidence at `unsure`. It is a promise already shipped to callers.

is a T row.

## Re-census (PRED orchestrator, 2026-10-25, main `2d5677e1`)

**The promise has changed since the question was asked.** "Permanent" is
gone from `crates/sweep/src/revolve/mod.rs`. `MultipleAxisRuns` now says
the two-run profile closes an inner cavity that "this construction has
no certified containment evidence for". It refuses under the cavity
invariant, with the recourse "revolve the solid profile and subtract
the enclosed body, or use a partial revolve".
`sweep/tests/revolve_errors.rs::two_axis_runs_in_full_revolve_are_typed`
pins the refusal on a C-profile. No test pins that a void exists.

The geometric claim looks true by a Jordan argument: the axis gap
between two runs is outside the profile, and with the boundary path
between the runs it bounds an exterior region that revolves to a cavity.

**So the live question is no longer "permanent or deferred".** It is
whether this case should be BUILT the way the holed full revolve is.
The ratified text:
- `crates/topo/README.md`'s structural conventions have that case born
  through the void-insertion door, "DEFINED as
  `revolve(outer) − revolve(hole-as-outer)`";
- `docs/DESIGN.md` `[topology.conventions]` says "Every cavity is born
  through one door".

That is verb breadth, and it goes to the designer pair before any `[ev]`
PR.

## Weighed (2026-10-25), and put to Ev

Both designers reached the same final state independently: **build it**.
A full revolve of a profile whose loop meets the axis in k ≥ 2 runs is
a manifold solid with k − 1 cavities. Each gap between two runs closes
a pocket outside the profile, which revolves to a cavity. The holed full
revolve's carried containment evidence applies unchanged: the profile's
simplicity pass separates non-adjacent segments in 2-D, and revolution
cannot bring points closer. So the construction is defined as
`revolve(filled) − Σ revolve(pocket)` through `topo::insert_void`, and
`MultipleAxisRuns` retires. The `[ev]` PR widens
`crates/topo/README.md`'s producer bullet to say so; that bullet is the
ratified text.

Both designers also found the sweep module header's "two or more runs
revolve to a non-manifold solid (D1)" false, whatever Ev decides. It
lands with the code. `NonManifoldAxisContact`, the isolated-vertex
pinch, stays.

## Ruled (Ev, PR 5680, 2026-10-25): build it

Ev's answer on the PR: "sounds good!" It approves the widened producer
bullet in `crates/topo/README.md`. The full revolve of a profile is
DEFINED as `revolve(filled) − Σ revolve(pocket)`, where the pockets are
its hole loops and the regions the gaps between its axis runs close,
executed through `topo::insert_void` with the profile's carried 2-D
margins. What is owed now is the unit that builds it:
- delete `MultipleAxisRuns`;
- have `axis::analyze_contact` return every run;
- have `full::build_wire` take a wire;
- build each pocket as a wire-case solid in hole-as-outer orientation,
  through the hole loop's `insert_void` call;
- key `Revolved::cavities` by origin;
- fix the module header's false "non-manifold" sentence.

The rows each designer named: the C profile (volume 2.75π, two shells,
tier 3 valid), a hollow sphere, k = 3, a hole together with two runs,
and no SSI run.
