## From GitHub issue 746

Opened 2026-08-20; 0 comments.

`tools/tess-lint`'s gate joins baseline rows to fresh rows on `(scene, face ordinal)` — `compare`'s `key` closure, `tools/tess-lint/src/lib.rs`. The face ordinal is a face's position in the body's face arena (D9 order), which is stable for a *given* body but is not a name: a kernel change that reorders a body's faces re-labels every row without changing any geometry.

**Both directions of that are live, and they are one defect — the key.**

1. **Compared against the wrong face.** A permutation that lands a baseline NURBS ordinal on a *different* fresh NURBS face makes the per-face recoverable-slack rule compare two unrelated faces. It can invent a finding or hide one.

2. **Silently dropped from the gate, which is worse.** When a permutation lands a baseline NURBS ordinal on a fresh **non**-NURBS face, `fresh_faces.get(&key(r))` misses, `recoverable()` is `None` on that row, and the loop `continue`s — the face leaves the comparison with **no finding at all**. The comment on that `continue` explains the miss as *"the scene's absence is already a Vanished finding"*, which is not what happened: the scene is present, only its ordinals moved.

**This is live today, not hypothetical.** #738 ran the sweep against the committed baseline and found `diefillet/diefillet` with **16 of its face ordinals permuted** — baseline face 0 is a sphere, fresh face 0 is a plane, and so on. It does not fire only because `diefillet` has no NURBS faces, so `recoverable()` is `None` on both sides. The same permutation on a scene with NURBS walls hits branch 1 or branch 2.

The hosted and local sweeps agree exactly on the permutation, so it is deterministic drift between main and the committed baseline, not machine noise.

**Not just a re-cut.** Re-cutting the baseline hides today's instance and leaves the key. What the gate needs is a join that survives face reordering, or an explicit refusal when the ordinal→chart mapping of a scene changes between baseline and fresh (the cheap version: a `Kind::Reordered` finding when a `(scene, face)` pair's `chart` differs, which is harness-breakage-shaped rather than a budget finding). Choosing between those is the unit's decision to make and record.

Scope: `tools/tess-lint/src/lib.rs` (`compare`, `Kind`, `Finding`), and whatever produces a stable per-face identity, which may reach `topo`/`mesh`.

Filed from #738's style review (SMELL-SCAN §D Track C row **C15**). Not fixed there: #738's subject was the `agreement` column, and closing this reaches outside `tools/`.
