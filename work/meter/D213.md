## What

**`tools/tess-lint/src/lib.rs`'s `Row::nurbs` documents a state the kernel cannot produce, and that sentence is the only stated reason `IDENTITY_COLUMNS` carries a sizing-block-presence entry.** The doc (target: `Row::nurbs`, `tools/tess-lint/src/lib.rs:206-215` at `e524b5671`) reads *"a `nurbs` face that reroutes off the lane keeps its chart and loses it. `IDENTITY_COLUMNS` reads both for that reason."*

The reroute cannot occur. `crates/mesh/src/tessellate.rs:135` routes `Surface::Nurbs(_) | Surface::Approx(_)` to `trimmed::tessellate_trimmed` unconditionally — there is no second arm for either. `crates/mesh/src/trimmed.rs:194-207` makes both of them `Lane::Nurbs` (the one exit is `Surface::Nurbs` holding a placeholder, which returns `Err` and so produces no patch and no row at all). `crates/mesh/src/trimmed.rs:703-706` notes a `FaceMeasure` for every armed face on that lane, and its `nurbs_stats` is `Some` for every `Lane::Nurbs` face by construction at `:252-291` — the only way to lose it is `per_cell_candidates(..)?` returning `Err`, which propagates out of `tessellate_trimmed` and again leaves the face without a patch. So a face reaching a row with chart `nurbs` and no sizing block does not exist in this tree.

The doc was already false before PR 1642. What that PR changes is that it is now **visible**: `tess_meter::sizing_of` panics on exactly that state (`(true, None)`), and since 1642 `FaceRow::csv_row` refuses it a second time at the writer, so the producing side cannot emit the row the sentence describes.

## Finding

Two consequences, both for whoever takes `C15`; neither is an edit to `C15`, which is open and design-gated.

1. **The sentence is the only stated reason `IDENTITY_COLUMNS` carries `"the sizing block"`.** `IDENTITY_COLUMNS` (`tools/tess-lint/src/lib.rs:915-924`) lists it second, and its own doc (`:912-914`) justifies it as *"the reroute case, where a face keeps its surface description and leaves the sized lane"* — the same claim. Removing the entry is not obviously right: it is what makes the precondition notice a producer that starts emitting the state, which is a schema change the lint should see. But the *stated* reason for it is false, and a reader re-deriving the column set from that sentence would reach the wrong conclusion.

2. **That entry is now a pure function of `chart`.** `identity()` (`:958-961`) builds it as `if r.nurbs.is_some() { "present" } else { "absent" }`, and with the reroute impossible `r.nurbs.is_some()` is exactly `chart ∈ {nurbs, approx}`. So it discriminates nothing the `chart` entry does not already discriminate. That weakens the module doc's census at `:154-157` — *"`chart` is `nurbs` on all 64 and the trim box is `0e0,1e0,0e0,1e0` on all 64, so five of the eight entries discriminate nothing there"* — to **six of eight by construction**, with `nu`/`nv` still the live pair. The count at `:145-152` (8 swap-invisible pairs, 16 of 64 sized rows) is a reading of the committed baseline and is not restated here; the *reason* the sixth entry is constant is structural and does not move with a re-cut.

**Verification status.** The chain above was re-walked against the tree for this filing, including the `?` inside `per_cell_candidates` that the review left unchased: it propagates out of `tessellate_trimmed`, so there is no path on which a `Lane::Nurbs` face produces a patch and no measurement. What is NOT re-walked: whether any consumer of `docs/tess-budget-data/` carries a committed row in the impossible shape from an older tree — the roster in `CHART_TAGS` is deliberately wider than today's producer for exactly that reason (see `tess-meter`'s `the_lints_roster_admits_every_tag_this_crate_emits`), so a baseline row predating the current lane split would still parse.
