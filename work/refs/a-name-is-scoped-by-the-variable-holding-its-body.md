The second unit of FORK-DM4 (`a-union-member-is-keyed-by-its-read`),
after the read key lands. NAMES N1 ("the scope"): a name is scoped by the
variable that holds its body, one name table per output variable. Built
evidence: the split's half segments and the pattern's `Instance { i }`
segment exist only to keep one node's table distinct by restating the
output. D10 text not yet built: `P1` and `P2` are two placements of `X`;
pinned into one space, a later `Place [P1, P2]` defines two outputs
carrying `X`'s rows verbatim (a placement adds no name segment, N1), which
a per-node `NameTable` refuses as `DuplicateName`; so this lands before
that placement is built.

The work:

- `NodeValue.name_table` becomes one table per output variable: a
  value's outputs each carry their names (`OutputNames`, private to the
  evaluator), and every reader reaches one through its read alone, by
  the one door `Evaluation::table(var)` (wire's read delegating to it).
  Node-level standing stays per node. A read of a split's port is a
  lookup of that port's table (`reads_projected`); the per-operand
  overlays that projected one node table onto a port retire with it;
  this is the target `part-split-half-retires` already names, so the two
  are built together or this one after it.
- A split's roles drop the half: `SplitBody(half)` becomes a plain body
  role, `SectionFace { side, section }` → `SectionFace { section }`, and
  likewise `SectionEdge`, `SplitFragment` and `CrossingVertex`. The
  intra-table qualifiers (`Keeps`, `Ends`) stay. The half is said once, by
  the variable a selection states or the read a `From` carries.
- N5 still diagnoses `PredicateFlip` from the split's recorded
  classification: a piece whose side flips when the plane moves leaves
  its variable's table rather than renaming, so the diagnosis cannot be
  read off the name (NAMES N2, the Split op's pieces). Pin it with a
  test that moves the plane across a piece.
- A part instance's per-output qualifier ("qualified by the copy") is the
  same rule; read `eval/parts.rs` before building and drop it if it only
  restates the output.
- What moves: every name with a split in its ancestry (the half dropped;
  `name_words_corpus`'s "the body above" changes its words), re-baselined
  and migrated at load by the same total map the first unit adds.

## Rulings taken while building (orchestrator, 2026-10-11, PR 4674)

- **(b) Resolution always names the read.** The one door is
  `resolve(ctx, at, name)` and its with-prior form; the bare
  evaluation-wide form is deleted, not kept for single-output nodes. A
  caller with no read to name is a finding.
- **(A) Appearance is keyed by (read, name)** (`SitedRef<VarId>`):
  `SetAppearance`, `SetAppearanceMeta` and `ClearAppearance` take the
  body read, the Python doors change with them, and stored files are
  regenerated by a one-shot map.
- **(d) Rebind never moves a key's read.** Moving a key to another read
  is a re-attachment, `SetAppearance` there and `ClearAppearance` here,
  with no new verb; `appearance_rebind_suggestions` offers (read, name)
  pairs, and split-out and inline re-attach a key whose read they take.
- **A reference whose read is gone is `ReadGone`** (N5's first rung,
  ahead of `NodeGone`; designers weighed it, Opus and Fable both for
  it): `ResolveError::ReadGone { name, read, edit: Deleted | Foreign }`,
  re-sited or removed, never rebound; a read that holds no body is a
  typed refusal (`ResolveRefusal::ReadNotAnOutput`), never a
  `Resolution`. It changes N5's ratified enumeration, so it waits on
  Ev's answer to the `[ev]` PR that asks it, as does the path scope
  gaining the read's node.
