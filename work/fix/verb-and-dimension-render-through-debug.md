The remainder of `error-types-with-no-display-class` (#1111) after its
viewer cut (#1741). Both were found by that cut's re-sweep, disclosed
there, and are **not** scheduled by it — this item is where they are
scheduled.

## `profile::path::Verb` has no `Display`

`crates/profile/src/path/program.rs:407` declares `Verb` — a public,
fieldless enum, generated by the same macro that declares `Step`. It
reaches a user surface at
`crates/viewer/src/sketch.rs:651`, where
`PreviewError::Transition` renders it `{verb:?}`:

```
"loop {loop_} step {step}: {verb:?} is not well-typed there — the tip is {}"
```

It is a genuine instance of #1111's class, in a **sixth** crate — one
that none of that issue's three fences covered. Fieldless, so the
`Debug` form is a bare variant identifier (`LineTo`) rather than a
struct dump: word-shaped, but a type identifier in a sentence, and one
that changes silently if a variant is ever renamed for internal
reasons.

Fix: `impl Display for Verb` in `profile`, on the LIB-DOORS-F6 shape,
naming each verb as a person would say it; then forward at the viewer
site. Note the declaration is macro-generated, so the impl either goes
in the macro beside `Verb::ALL` or is written out per variant — that
choice is the only real decision here.

## `Dimension` renders through `Debug` in four UI labels

`Dimension` HAS a `Display` (`editor-core`), and four viewer labels
render it through `Debug` anyway:

- `crates/viewer/src/app.rs:2832` — `format!("parameter {} ({:?})", row.name.0, row.dimension)`
- `crates/viewer/src/app.rs:4339` — `ui.weak(format!("{:?}", row.dimension))`
- `crates/viewer/src/app.rs:4362` — `ui.weak(format!("{:?}", family.dimension()))`
- `crates/viewer/src/session.rs:750` — `"parameter {} already exists ({dimension:?}) — edit it instead?"`

Same defect shape as #1111's — a consumer composing a `Debug` rendering
where the payload names itself — but `Dimension` is not an error type,
which is why the viewer cut reported these rather than absorbing them.
Fix is mechanical: forward. The one thing to check is that
`Dimension`'s `Display` reads correctly inside a parenthetical, since
that is where three of the four sit.

## What landed

**`Verb` gets a `Display`, generated by the table.** The word the verb
is CALLED rides its row — `verb LineTo(Target<T>) = "line_to" bind …` —
so `transition_table!` expands it into the `Verb` tag's `Display`
alongside the tag itself, and the verb's name vanishes with the row
exactly as the typed method, the driver arm and the `Step` variant do.
The word is the ALGEBRA'S OWN SPELLING (`line_to`, `arc_fillet`), which
is what the author wrote and what the row's combo already offers.

The viewer's `PreviewError::Transition` forwards to it. It is the one
site that moves: `profile`'s own `ReplayError` and `editor-core`'s
`ProgramFault::Lattice` render the same pair as the transition table's
COORDINATE and say in their own comments why — that rule is intact and
now states which sentence is which.

`crates/profile/tests/path_program.rs` pins the Display over
`Verb::ALL` in two directions (no verb says its variant identifier, no
two verbs say the same word); `crates/viewer/tests/path_authoring.rs`
pins the rendered preview sentence on the chain that produces it.

**The `Dimension` half was already discharged** — by `b62a14e1` (PR
2053, VIEW, 2026-09-06), which carried all four labels through
`Dimension`'s `Display` and left the rule's reason at each site. The
files had moved (`app.rs` -> `pane/properties.rs`, `session.rs` ->
`session/refuse.rs`), which is why the item's line citations no longer
resolved. Re-swept: no `Dimension` reaches any user surface through
`Debug` anywhere in the tree.

**Roster move.** `prose_census.rs`'s `UNDECIDED` named
`crates/viewer/src/sketch.rs` / `PreviewError` / `verb`; that site is
gone, so the entry is deleted. The row compares in both directions, so
the deletion is the row working.
