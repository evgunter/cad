## What

**The `code_only`-locate → `balanced_end` → `top_level_split` → read-the-element-out-of-another-view composite is implemented twice, independently, and the two already differ.** `crates/test-utils/src/source.rs` is the shared home for source-text guards (`D205`, `S117`), and it exposes the *parts* — `keeping`, the three views (`code_only`, `code_and_literals`, `comments_only`), `balanced_end`, `top_level_split`, `rust_sources`, `crate_dir`, `suite_files` — but nothing that decodes a literal's value and nothing that composes the locate-and-read walk. So each caller composes it again.

The two implementations (`flagged_census.rs` line numbers relative to `e524b5671`; the `tess-meter` half is cited by target name, since this PR renumbers that file):

- `crates/geom-core/tests/flagged_census.rs:159-197`, target `calls_in` — locates `decide_flagged` in `source::code_only`, takes `balanced_end` of the argument list, `top_level_split`s the arguments, takes the fourth, and reads it out of **raw `text`** through `ledger_row` (`:199-208`).
- `tools/tess-meter/tests/derivations.rs`, targets `string_array` and `plain_string_literal` — locates a declaration head in `source::code_only`, finds the `=` then the `[`, takes `balanced_end`, `top_level_split`s the initializer, and reads each element out of **`source::code_and_literals`** through `plain_string_literal`.

**The drift is at birth and it is the interesting half.** Reading the located element out of raw `text` and reading it out of `code_and_literals` are different guards: over raw text a comment inside the argument list is still there and can appear in the value; over `code_and_literals` it is blanked and only the literal survives. Neither file argues for its choice against the other, because neither knows the other exists. That composite — not the quote-strip, which is three characters of `strip_prefix`/`strip_suffix` — is the thing that wants one home.

## Finding

What the shared shape has to decide, which is why this is a row and not a patch:

- **Which view the element is read out of.** The two callers answer differently today. A shared composite either takes the view as a parameter — which makes the choice explicit at each call site, and is the shape `lint_view`'s equal-offsets property already supports — or picks one and the other caller changes behaviour.
- **What "the value" of an element is.** `plain_string_literal` refuses everything but a plain double-quoted literal; `ledger_row` panics with a long message saying the same thing. Escapes, raw strings and `concat!` are refused in both, deliberately, and a shared home should keep the refusal rather than grow a decoder.
- **Whether the locate half is one operation or two.** `flagged_census` locates a call (`ident` + optional turbofish + `(`), `string_array` locates a declaration (`decl` + `=` + `[`). The bracket walk and the split are common; the head-matching is not.

`crates/test-utils/tests/reader_census.rs` is the ledger that keeps this population honest and is the instrument this row answers to.

## Re-derived (2026-09-15, lane A)

**VERDICT: PARTIAL.** The composite is still implemented twice and the
drift the row calls *"the interesting half"* is still there, unrepaired.
But the row's premise — *"`test_utils::source` has no home for it"* — is
now **wrong on three of its four parts**: the decoder, the view-agreement
guard and the declaration-locate half all landed in
`crates/test-utils/src/source.rs` since the row was written, and
`tess-meter`'s half uses all three while `flagged_census`'s half uses
none of them.

### What the shared home has gained (the row's API list is stale)

The row lists `source.rs` as exposing *"`keeping`, the three views
(`code_only`, `code_and_literals`, `comments_only`), `balanced_end`,
`top_level_split`, `rust_sources`, `crate_dir`, `suite_files`"* and
*"nothing that decodes a literal's value and nothing that composes the
locate-and-read walk."* Re-derived (`grep -n '^pub fn\|^pub enum\|^pub mod'`
over `source.rs`, now 1504 lines), it also exposes:

- **`plain_string_literal`** — *"the value of a plain string literal, or
  `None` where `text` is not one"*, refusing `concat!`, raw strings and
  escapes exactly as the row wanted the refusal kept. **The decoder now
  has a home.**
- **`blanked(view, searched, text)`** — *"`view(text)`, refused unless it
  is `text`'s bytes blanked IN PLACE"*, whose doc states this row's
  problem in this row's terms: *"Every pin that LOCATES a declaration in
  one view and READS its value out of another depends on the two views
  agreeing byte for byte, and each such pin asserted that for itself."*
- **`initializers` / `sole_initializer`** — the declaration-locate half,
  head → `;`, with the *"declared N times, not once"* refusal.
- **`item_body` / `angle_end` / `sentinel_region` / `line` /
  `boundary_before` / `file_module_decls` / `aggregation_violations`.**

So the row's third decision — *"whether the locate half is one operation
or two"* — has been answered for **declarations** and left unanswered for
**calls**, which is the half `flagged_census` needs.

### The drift is unrepaired, and it is now asymmetric

Re-derived at both call sites, by target name:

- **`crates/geom-core/tests/flagged_census.rs`, `calls_in`** (the row's
  `:159-197`, still `:159`): locates `decide_flagged` in
  `source::code_only`, hand-rolls the identifier/turbofish head match,
  `source::balanced_end`, `source::top_level_split`, takes
  `cite.get(3)`, and then reads the element **out of raw `text`** —
  `ledger_row(&text[args + cite.start..args + cite.end])`. Its
  `ledger_row` (the row's `:199-208`, now `:201`) **still hand-rolls the
  quote-strip** (`strip_prefix('"')` / `strip_suffix('"')` with its own
  panic) although `source::plain_string_literal` now exists.
- **`tools/tess-meter/tests/derivations.rs`, `string_array`**: locates
  the declaration head in the code view, `=` then `[`,
  `source::balanced_end`, `source::top_level_split`, and reads each
  element out of **`literals[at]`** — the `code_and_literals` view —
  through `source::plain_string_literal`. Its sibling
  `lint_view`/`lint_literals` go through `source::blanked`.

**Neither file argues for its choice against the other. Still true.** And
the asymmetry the row did not have: `string_array` asserts the two views
agree (`assert_eq!(code.len(), literals.len(), "the two views are the
same bytes, blanked differently")`, and `source::blanked` does it again
for the cached views), while **`calls_in` indexes `text` with offsets
derived from `code` and asserts nothing at all** — it relies on the
property `source::blanked` exists to refuse, and does not call it. That
is the sharper form of the row today.

### Recommendation

Keep open, and narrow the What: the row should now read *"the
CALL-locate half and the compose have no home; the decode, the
view-agreement guard and the declaration-locate half do, and one of the
two callers uses them while the other does not."* The residual unit is
smaller than filed and its shape is clearer: give `source` a call-locate
to match `initializers`, decide the view at the call site as
`lint_view`'s equal-offsets property already supports, and move
`ledger_row` onto `plain_string_literal` and `calls_in` onto `blanked`.
