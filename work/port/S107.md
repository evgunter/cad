## Question

**The `DimensionError` untangling renamed the Rust type and left the
Python-visible confusion in place**, now defended in prose. Is that a
defect or a deliberate compatibility choice — and if deliberate, may the
tree stop re-documenting it?

## Gates

`crates/pncad-py/` is Track U's. If a defect, the Python-visible rename
is a U row; if deliberate, the cross-referencing docstrings and the
`errors.rs` paragraph that re-document it are what the ruling licenses
trimming. #694 schedules the `load`-door half either way.

## Finding

`DimensionError` → `QuantityOpMismatch` is a Rust-side rename only
(`crates/pncad-py/src/errors.rs:52-61,115-131,172-176`). From Python,
`DimensionError` still means the quantity-operator check, and the
document layer's real `DimensionError` still surfaces as `LiteralError`
on one door and as `PersistError` with `variant == "parse"` on the other
(`pncad.pyi:83-108`). The situation the first scan named — the real
dimension checker not being the thing called `DimensionError` — is
preserved and now defended by cross-referencing docstrings on both
classes plus a paragraph in `errors.rs`. Tag strings are correctly
unmoved and #694 schedules the `load`-door half; the naming half was
closed by argument rather than by change, and the length of the argument
is what draws attention to it.

**Verdict: a defect.** Ruled by Ev in-chat on 2026-09-15, on the
general principle that *Python should always match Rust where it can*.
The compatibility reading the finding offered as the alternative had no
installed base to protect — `publish = false` and the project has no
name yet (Q9) — so the naming half was closed by argument where a rename
was available.

The ruling does **not** license trimming the cross-referencing
docstrings as documentation of a deliberate choice; it deletes them as
the reconciliation of a defect, along with the confusion they reconcile.

The work it releases is
`python-dimensionerror-names-the-quantity-check-not-the-dimension-check`
on this slate, filed the day the ruling landed. The `load` door's half
stays `load-path-stringifies-structured-refusals`, and the two are one
door: which class the document layer's refusals arrive as is decided
across both.
